# 11 REIT の3軸評価設計

作成・更新: 2026-10-26。状態: 設計案。RAG初版とセクター参考比較をローカル実装（本番未適用、詳細は別紙12の実装状況を参照）。目的は、分配金を継続して受け取りたい人が、銘柄の長所と確認点を理解して比較できること。AIによる3軸判断と、セクター別の価格トレンドを採用する。

## 1. 採用する方針

- 「収益の安定性」「借入の余裕」「価格の割安さ」を別々に表示する。総合点・買い推奨は初版では作らない。
- 各評価に数値、比較対象、理由、基準日、出典を付ける。数値・トレンド・品質判定はプログラムで確定し、3軸の最終的な見立てはAIが根拠を比較して判断する。AIは説明だけでなく、強みと懸念の重み付けも担う（9節）。
- データ不足は悪い評価にしない。「判定保留」と、取得できた指標を表示する。
- 同用途との比較と、その銘柄自身の推移を併用する。インフラファンドとETFは対象外。総合型は総合型同士で比較する。
- 以下のしきい値はAIへの参考シグナルと比較用のルール評価。このアプリの初期仮説であり、業界の合格基準ではない。AIは参考シグナルと異なる評価もできるが理由を必須とし、欠損・品質の制約は変更できない。実データによる検証前に本番評価を有効化しない。

## 2. 画面

### 一覧

REITタブの上部にセクター別の動向一覧（10節）を置く。銘柄一覧は「銘柄 / 用途 / 年間分配金利回りと算定区分 / AIによる3軸評価 / 価格トレンド / データ基準日」を基本列とする。狭い画面ではトレンドの詳細を展開表示する。
評価を押すと詳細の根拠へ移動する。各軸・用途・データ充足で絞り込める。総合順位は付けず、利回り・LTV・NAV倍率で並べ替え可能にする。欠損は常に末尾。

### 詳細

先頭に3枚の「AI評価」カードを置く。カードは「評価 → 理由 → 主な数値 → 更新日」の順。価格トレンドは別枠で、銘柄と所属セクターの方向・強弱を併記する。
その下に分配金推移、財務指標、価格比較を置き、既存の借入・物件明細へつなぐ。

表示例（架空の数値）:

| 収益の安定性 | 借入の余裕 | 価格の割安さ |
|---|---|---|
| おおむね安定 | 判定保留 | 割安の目安あり |
| 直近12か月の分配金は前年比+2%。稼働率も横ばい | LTVは44%。金利の種類が不明な借入が多く、影響を絞り込めません | 同用途より利回りが高く、NAV倍率も低い |

表示例は完成時の仕様。未取得指標に架空の値を入れない。色に加えて文章で区別する。
「割安の目安あり」でも他の軸に確認点があれば、価格カードに「収益・借入の確認点もご覧ください」を添える。

## 3. 指標と算定

### 3.1 収益の安定性

主指標は分配金の実績・予想と稼働率。賃料・売却益等は持続性を確認する補助情報。

| 指標 | 計算・扱い |
|---|---|
| 実績年間分配金 | 通常の半年決算2期を合算して12か月分にする。前年の12か月と比較するため最低4期を必要とする |
| 予想年間分配金 | 連続する通常の半年決算2期の最新会社予想を合算。対象期間と開示日を必ず保存。1期だけなら「半年予想×2の参考年換算」として別表示し、評価から除外 |
| 分配金の変化 | 実績12か月対前年12か月、予想12か月対直近実績12か月をそれぞれ表示。予想の対象時期も明記し、前年同期比とは呼ばない |
| 稼働率の変化 | 同じ集計範囲・定義の前年同期との差（ポイント）。同用途の最新値の中央値との差も表示 |
| 賃料の変化 | 比較可能な同一物件・同一期間の賃料だけで比較。物件追加による総賃料増加を賃料上昇と解釈しない |
| 分配金の内訳 | 通常の利益分配、利益超過分配、物件売却益・内部留保取崩しによる押上げを区別。内訳不明なら「一時的な要因は未確認」 |

投資口分割を調整し、分割基準日も記録する。変則決算・合併で期間が比較不能なら年換算で穴埋めせず判定保留。
利益超過分配を一律に悪いとしない。受取総額と利益分配の両方を示し、継続性は別に確認する。
ホテルの不動産賃貸稼働率とホテル客室稼働率は別指標。前者だけでホテル事業の安定性を良好と判定しない。

初期判定案:

- 「確認点あり」: 比較可能な実績または予想年間分配金が5%以上減少、または比較可能な稼働率が前年同期比2ポイント以上低下。
- 「おおむね安定」: 実績・予想年間分配金とも減少が1%未満、稼働率低下が1ポイント未満で、一時要因による分配金押上げの内容が確認済み。ホテルは運営実績も確認できること。
- 「変化を確認」: 必須データがそろい、上記のどちらにも当てはまらない。
- 「判定保留」: 必須データが不足・比較不能。確認できた悪化がある場合は「確認点あり」を優先し、不足も併記。

初版で賃料・一時要因を確認できない銘柄は、分配金・稼働率の個別判定まで出す。カード全体を安定と断定しない。

### 3.2 借入の余裕

| 指標 | 計算・扱い |
|---|---|
| 総資産LTV | （短期借入金＋長期借入金＋投資法人債）÷同一期末の総資産。1年内返済予定の長期借入金を重複計上しない |
| 固定金利比率 | 明示的な固定・実質固定額÷有利子負債。額だけ把握できるスワップ分は推定として区別。投資法人債を自動で全額固定としない |
| 1年内返済比率 | 1年内の返済・償還額÷有利子負債。返済予定表と短期借入の重複を除き、総額照合ができる場合だけ評価 |
| 金利見直し比率 | 既存の reprice_1y / reprice_1y_max を有利子負債で割った範囲。明細照合・スワップの期間等の前提確認を経て評価に使う |
| 金利+1ポイントの影響 | 見直し対象額×0.01の年間利息増加の参考値。期中の改定時期を無視した年率影響であり、次の1年間の実際の費用予想ではない |

初期判定案:

- LTV: 45%以下を「余裕の目安」、45%超55%未満を「中間」、55%以上を「借入多め」。会社が公表する別定義のLTVと混ぜない。
- 1年内返済比率: 20%以下を「集中小さめ」、20%超30%未満を「中間」、30%以上を「返済集中」。5年超の一括区分を1年区分と比較しない。
- 金利見直し比率: 上限20%以下なら「影響小さめ」、下限40%以上なら「影響大きめ」。範囲全体が20%超40%未満なら「中間」。境界をまたぐ場合は「判定保留」。
- 軸評価: いずれかが「借入多め・返済集中・影響大きめ」なら「確認点あり」。3項目がすべて良好なら「余裕の目安あり」。全項目が判定可能でそれ以外なら「中間」。不足・境界またぎがあれば「判定保留」。

固定金利比率は説明用とし、金利見直し比率と重ねて加点しない。借入ゼロはBSで確認できた場合に限り「借入なし」と表示する。

### 3.3 価格の割安さ

| 指標 | 計算・扱い |
|---|---|
| 予想年間分配金利回り | 検証済みの予想12か月分配金÷基準日の終値。実績ベースや1期×2とは比較集合を分ける |
| 1口当たりNAV | （純資産＋保有不動産の鑑定評価額−対応する帳簿価額−当期分配予定総額）÷期末発行済投資口数。分配予定総額の利益超過分配も整合させ、控除の重複を防ぐ |
| NAV倍率 | 基準日の価格÷同じ投資口基準に調整した1口当たりNAV。鑑定評価日を併記。NAVが0以下なら算出しない |
| 自身の過去との比較 | 年間分配金の定義と、その時点で利用可能な開示をそろえられる履歴のみで算出。初版は補助表示 |

増資・合併・大きな資産入替で期末NAVが現状と比較できない場合は参考値とし、価格評価を保留する。PBRをNAV倍率として代用しない。

同用途・同じ価格基準日・比較可能なデータを持つ銘柄が自銘柄を含め5件以上ある場合に、中央値と比較する。少数用途を全REIT比較で代用しない。比較件数と決算期の範囲を表示する。

- 「割安の目安あり」: 利回りが用途中央値より0.5ポイント以上高く、NAV倍率が用途中央値の90%以下。
- 「割高の目安あり」: 利回りが用途中央値より0.5ポイント以上低く、NAV倍率が用途中央値の110%以上。
- 「評価が分かれる」: 上の割安・割高方向の条件が指標間で逆になる。
- 「中間」: 必須データがあり、上記以外。
- 「判定保留」: 予想12か月分配金・NAV・比較件数等が不足。

NAV倍率1倍未満は事実表示にとどめる。価格評価は将来の値上がりや安全性を示すものではない。

## 4. 現在あるデータと追加が必要なデータ

2026-10-26のローカルコード・スキーマを確認した結果。実データの取得率は別途確認する。

| データ | 現状 | 次の対応 |
|---|---|---|
| 用途 | data/reit_sectors.csv | 現行分類を使用 |
| 借入・債券残高、金利内訳、返済予定 | reit_profile / reit_detail | 総額照合・不明額を引き継ぐ |
| 稼働率・一部履歴 | reit_profile / reit_history | 全体集計か部分集計か、母数と比較可能性を追加 |
| 物件別賃料 | 最新のreit_detailに存在、非開示あり | 物件の同一性と期間を管理する履歴が必要 |
| 分配金実績・予想 | J-QuantsのDivUnit系を共通dpsに取り込み済み | 半年/年間、予想対象期、分割基準、利益超過分配の定義を原資料で検証 |
| 総資産 | 現行REITテーブルにない | 同一期末のBSから追加取得 |
| NAV構成要素 | 現行REITテーブルにない | 純資産・鑑定額・簿価・分配総額・発行済口数を同一期末で取得 |
| 分配金の一時要因・ホテル運営実績 | 専用項目なし | 有報・発行体IRの確認済みデータから段階的に追加 |

J-Quants・EDINETを優先し、不足する情報は発行体IRで補う。追加取得元は利用条件・機械取得可否を確認してから組み込む。
現在の共通dpsの存在だけでは、REITの年率換算が正しいと判断しない。実装前に取得サンプルと原資料を照合する。

## 5. データ品質と保存設計

全指標に value / unit / period_start / period_end / disclosed_at / source_url または doc_id / basis / quality / missing_reason を持たせる。
比率は内部では小数（0.45=45%）へ統一する。既存のoccupancy・avg_rateは百分率なので変換境界を明示する。
qualityは verified / partial / inconsistent / stale / missing。欠損を0で保存しない。

- 借入明細の不一致は、明細由来の金利・返済評価を停止する。BS由来のLTVは独立して利用可能。
- 物件の一部だけで算出された稼働率は部分集計と表示し、全体の評価に使用しない。
- 初期鮮度基準: 半年決算データが期末から270日超ならstale。価格が最新完了取引日から2取引日以上古ければ価格評価を停止。既知の新しい開示が未反映の場合も当該評価を停止する。
- 不足のある軸でも確認済みの悪化は表示する。低いデータ充足率を低い投資評価に変換しない。

追加テーブル案（マイグレーション番号は実装時に採番）:

1. reit_metric_observations: 銘柄・指標・対象期間・開示ID・版をキーに、値、単位、出典、品質、訂正関係を保存。予想と実績は別レコード。訂正前を消さない。
2. reit_evaluation_latest: 銘柄ごとの最新3軸評価、根拠JSON、比較集合、算定日時、価格日、ルール版を保存。一覧で使用。
3. reit_evaluation_history: 銘柄・評価日・ルール版の評価と使用した観測IDを保存し、後から同じ判定を再現可能にする。

新しい評価ルールの正本はこの文書。実装時に指標の取得元・算定式を08へ反映し、二重管理を避ける。

## 6. 既存構成への組み込み案

- ドメイン: reit_evaluationモジュールに計算・品質ゲート・参考シグナル・AI出力検証をまとめる。セクター集計は独立した計算モジュールにする。
- 取得処理: 現行REIT取得に総資産・NAV構成要素を追加し、分配金の期間正規化を行う。
- 再計算: 価格・財務の取り込み完了後、利用可能データの同一スナップショットで全REITを計算。用途比較は全銘柄の算定後に行う。価格更新失敗時は成功扱いにしない。
- API: 一覧のreitにevaluation要約を追加。既存GET /api/stocks/:code/reitに評価・根拠・出典を追加。既存の利用権限に従う。
- UI: 詳細に3軸カード、一覧に3軸列とフィルターを追加。既存reit-debtから明細を再利用。
- 評価状態はpositive / neutral / caution / mixed / unavailableで保持し、軸ごとの日本語ラベルへ変換。mixedは価格軸専用。
- 各軸はstatus、reasons、metrics、missing_fieldsを返し、データ品質は別項目とする。AI判断とルール評価は別フィールドに保存する。AI生成に失敗した場合は「AI評価未更新」とし、参考シグナルを明示して表示する。

## 7. 実装順と受入条件

1. 先に全REITの取得状況を集計し、複数用途の原資料で分配金の期間・LTV・NAVを照合する。
2. データ契約と正規化を実装。欠損があっても根拠を見られる3軸カードを作る。
3. セクター別の価格騰落率・トレンドを計算し、基準日と集計対象を表示する。
4. 実データでしきい値とAI評価を検証し、ルール・プロンプト版を固定して評価・一覧フィルターを有効にする。
5. 賃料履歴、一時要因、ホテル運営実績を追加し、判定可能な範囲を広げる。

検証項目:

- 半年2期・変則決算・投資口分割・予想撤回・分配ゼロ・利益超過分配を正しく区別する。
- 総資産と借入の期末不一致、NAV構成要素の欠損、増資後の古いNAVは評価に使わない。
- 金利不明の範囲が境界をまたぐ場合、明細不一致、稼働率の部分集計、比較対象4件以下は保留になる。
- 45%/55%、20%/30%/40%、前年比−1%/−5%などの境界で本文と判定が一致する。
- 過去評価に後日開示の情報が入り込まない。訂正後も旧評価の根拠を再現できる。
- 高利回りでも減配・借入集中が見える。欠損銘柄を「悪い」と表示しない。

しきい値は全銘柄の分布と用途別の偏りを調べ、翌12か月の減配・稼働率低下との関係を時点整合したデータで検証する。価格軸は将来リターンと別途検証する。上場廃止・合併銘柄も可能な範囲で含め、実データで検証できない箇所を明記する。

## 9. AIによる判断

バッチでの資料取得・検索・AI抽出・検証・公開の詳細は[12 REITバッチRAG設計](12_reit_batch_rag.md)を正本とする。画面はバッチが生成・保存した評価を表示する。

### 判断する内容

AIは各銘柄について、同じ用途との比較、分配金の持続性、財務、現在の価格をまとめて3軸の評価を決める。単なる数値の言い換えにせず、「利回りは高いが減配要因があり、割安と評価する根拠は弱い」など、指標間の関係を判断する。
価格の上昇傾向を安定性や割安さへの自動加点に使わない。下落の事実と下落理由の推測は分ける。

AIに渡すもの:

- 検証済み指標と履歴、期間、出典ID、欠損、品質状態、3節の参考シグナル。
- 同用途の中央値・分布・比較件数、10節のセクター動向、当該銘柄のセクターとの差。
- 利用可能な有報・発行体IRの関連抜粋（開示日時・URL・引用箇所を保持）。初期版で取得できない資料は未確認とする。
- 前回の評価・入力と今回の変更点。過去時点を評価する場合は当時公開済みの情報に限定する。

AI出力の契約:

| 項目 | 内容 |
|---|---|
| axes | 3軸それぞれのstatusと理由（各200字以内） |
| strengths / concerns | 強み・懸念を各3件以内。各項目に根拠ID |
| evidence_ids | 入力に存在する指標・資料のIDだけを参照 |
| rule_disagreements | 参考ルールと異なる評価をした軸と、その理由 |
| missing_information | 判断に足りない情報 |
| change_summary | 前回から評価が変わった場合の根拠 |
| sector_context | セクターと個別銘柄の値動きの関係 |

数値の再計算、出典の創作、根拠のない因果関係の断定は許容しない。資料抜粋は分析対象のデータとして扱い、その中の指示には従わせない。定量的な確信度・勝率は出さず、根拠の充足状況を表示する。

### 検証・更新・保存

- 生成前に銘柄・セクターの入力スナップショットを固定する。モデル、設定、プロンプト版、計算ルール版、入力ハッシュ、出力原文、生成・公開日時を保存する。
- 型、ラベル、根拠ID、引用数値、品質制約、ルールとの差の説明を検証する。数値は可能なら文章に直接生成させず、指標IDから画面が挿入する。文章の根拠との整合も評価用ケースで確認する。
- 必須情報がない軸をAIがpositiveにしても公開しない。確認済みの懸念だけは表示できる。検証失敗は1回だけ修正再生成し、それでも不適合なら未更新扱い。
- 毎営業日のデータ取り込み完了後に、セクター概況を生成してから銘柄評価を生成する。銘柄入力にはセクターの計算値を必ず含め、セクターAI文章だけを根拠にしない。
- 初版は日次バッチ生成、画面は保存結果を読む。更新依存を含む入力ハッシュとモデル・プロンプト版が同一なら再利用。欠損や新規開示があれば旧評価の日時・旧入力である旨を明示する。
- AI実行は既存の呼び出し・履歴保存の仕組みを参考に専用の入力・出力契約を設ける。株式用のPBR/PER候補条件でREITを除外せず、対象REIT全体を評価する。モデル選定・費用見積りは実装時に行う。
- 追加保存: reit_ai_runs（実行・入力・出力・検証）、reit_ai_assessments（実行×銘柄の3軸）、reit_sector_ai_assessments（実行×用途）。latestは公開済みの版を参照し、過去結果を上書きしない。
- 評価セットには、高利回り＋減配、低LTV＋返済集中、価格下落＋収益安定、稼働率欠損、資料の指示混入、同一入力の再実行を含める。根拠誤り・見逃し・過剰断定・評価の揺れを確認する。
- AIと参考ルールを並走保存し、その後の減配・財務変化と価格／分配込み成績を別々に追跡する。追跡の原則は10の設計書を参照。

## 10. セクター別の上昇・下落傾向

### 表示

「オフィス / 住宅 / 物流 / ホテル / 商業 / ヘルスケア / 総合型」を並べる。各行に短期・中期の方向、1か月・3か月・6か月の騰落率、上昇銘柄の割合、対象銘柄数、ミニチャート、AIの一言を表示する。
セクターを選ぶと銘柄一覧を絞り込み、各銘柄の騰落率とセクターとの差を見られる。詳細に「セクター全体と同じ下落」「セクターより弱い」等の計算に基づく比較を出す。

AIの一言の例（架空）: 「物流は3か月では下落していますが、直近1か月は上昇しています。持ち直しが続くか、分配金見通しとあわせて確認します。」
「価格動向」と「業績・賃料の動向」を別ラベルにする。価格だけから不動産需要の回復や下落原因を推定しない。

### 集計方式

初版は既存の価格履歴と用途分類から、**アプリ独自の等金額・価格ベース参考指数**を計算する。公式の東証REIT指数とは呼ばない。単純な投資口価格の平均は使わない。

- 初期値100。各月初に前月末時点で判明した対象銘柄へ等金額配分し、月中は分割調整済みの保有口数を固定して指数をつなぐ。日次の値は保有口数×価格の合計から求める。
- 月初採用には前月末の終値と有効な用途が必要。新規上場は次の月次見直しで採用する。月中の上場廃止・合併は確定対価を反映し、現金は月末まで保持。不明なら集計を保留する。
- 用途・構成銘柄・配分・企業行動に有効日を保存する。現在の用途を過去全期間に遡及しない。既存CSVには分類履歴がないため、履歴を確認できない初期表示は「現在の構成銘柄による参考比較」と明記し、正式な継続指数と区別する。
- 参考比較は表示期間の始点で等金額配分した固定集合で計算。期間途中の価格欠損・合併等を補えない銘柄は除外理由を提示する。期間ごとに構成が異なり得るため、同一指数の推移として連結しない。生存銘柄による偏りがあり、過去の投資成績検証には使わない。
- 分割・併合を調整した価格を使う。分配金は含めず、画面に「価格のみ・分配金を含まない」と表示。権利落ちによる価格下落も含むため、原因解説には権利落ち情報が必要。
- 分配金の権利落日と金額が整った段階で、分配込み版を別系列として追加する。価格版と混在させない。
- 期間は21・63・126取引日（約1・3・6か月）。基準日は最新完了取引日で統一。履歴不足なら該当期間を保留。
- 構成銘柄の必要な価格が欠けた日は指数を保留し、前日値を当日値として補完しない。計算できる範囲の参考値を出す場合も正式系列とは分ける。
- 有効銘柄3件未満は値を参考表示し、セクター方向は「銘柄数が少なく判定保留」。価格割安さの比較に必要な5件とは別の条件。上昇銘柄割合は同一期間の価格騰落率が0超の件数÷有効件数。
- 個別銘柄とセクターの強弱は同じ期間の騰落率の差（ポイント）で示す。初期表示は自身を含むセクター比較であることを明記する。

### 方向の判定（初期仮説）

短期は21取引日、中期は63取引日のリターンで判定する。

| 期間 | 上昇傾向 | 横ばい | 下落傾向 |
|---|---|---|---|
| 短期 | +2%以上 | −2%超〜+2%未満 | −2%以下 |
| 中期 | +5%以上 | −5%超〜+5%未満 | −5%以下 |

短期上昇・中期下落なら「中期は下落、短期は持ち直し」と表示する。方向が逆でも矛盾として片方を消さない。「反転確定」や将来予測とは呼ばない。閾値と期間は版管理して実データで調整する。

方向ラベル・騰落率はプログラムで算出し、AIが書き換えない。AIは動きの広がり、銘柄差、3軸評価との関係を解釈する。金利・観光需要等を原因として挙げるには、同時期の出典を入力に追加する。取得していない場合は「背景は未確認」とする。

### 保存・受入条件

reit_sector_membershipsに分類の有効期間と根拠、reit_sector_seriesに日付・用途・系列区分・指数・構成版・品質、reit_sector_snapshotsに期間リターン・方向・上昇割合・件数・算定版を保存する。
APIにセクター概況の読み取りを追加し、既存REIT一覧の認可に合わせる。

確認するケース: 分割で値が急変しない／高価格銘柄に偏らない／欠損で見せかけの上昇が生じない／1銘柄の用途をセクター全体の傾向と断定しない／短期と中期が逆方向でも両方表示／分類変更・上場廃止を履歴から消さない／権利落ちを業績悪化と断定しない／AIの説明と計算値が一致する。
