# 02 非機能要件

> 出典: Claude Docs「増配期待株ダッシュボード 要件定義」（rev 56, 2026-10-21）

## 無料枠の制約

無料で作りきるうえでの最大の壁は、Workers無料プランの「1回の実行あたりCPU 10ms」と「メール送信が検証済みアドレスに限られること」の2つ。他の枠は個人利用なら十分。

| サービス | 無料枠（2026年10月時点） | このアプリでの影響 |
|---|---|---|
| Workers（API・Cron） | CPU 10ms/回、サブリクエスト50/回、Cron 5本、メモリ128MB | 画面のAPIは十分。全銘柄の取得・有報の解析を一度にやるのは無理 |
| Workflows | 1ステップCPU 10ms、1インスタンス1,024ステップ、同時100インスタンス | 株価取得を1銘柄1ステップに分ければ可能。有報の解析は10msを超える恐れ |
| Workers AI | 1日10,000 Neurons（Llama 3.1 8B fp8-fastで入力約240万トークン相当） | 候補50銘柄の毎日のレコメンドと配当方針の抽出なら収まる。方針抽出は数日に分ける |
| D1 | 5GB、読み取り500万行/日、書き込み10万行/日（要確認） | 日次更新は約1万行/日で余裕。過去10年の週次株価（約200万行）はD1に入れずR2に置く |
| R2 | 10GB、書き込み100万回/月（要確認） | 銘柄ごとの履歴ファイルと有報の生データ置き場 |
| メール送信 | Cloudflare Email Serviceは無料プランでは検証済みの宛先にしか送れない（任意の宛先は月$5の有料プラン） | メールは管理者だけに送るため、管理者のアドレス1件を検証済みの宛先にして無料で送れる（送信元はmaa-un.comのアドレス） |

- **認証の安全性**: 本人確認はGoogle SSO（Clerk経由）だけで、アプリはパスワードを保存しない。すべてのAPIでセッショントークンと許可リストを確認する。ログイン記録は1年保存
- **データ分離**: ユーザー固有データの取得・更新は、リポジトリ層で必ずuser_idを条件に含める
- **表示速度**: 一覧は終端での初回表示1秒以内を目安。指標は事前計算済みの1表から読む
- **見やすさ**: PCとスマホの両方に対応。ダークモード対応。数字は右寄せ・桁を揃える。色は「割安=緑、割高=赤、警告=黄」だけに意味を持たせる
- **障害時**: バッチ失敗は管理者にメール。画面は前回のデータで表示し続ける
- **免責表示**: 「情報提供のみ。投資判断は自己責任」をフッターとメールに記載

## 非機能要件一覧

IPA「非機能要求グレード」の6分類（可用性・性能・運用保守・移行・セキュリティ・環境）に、キャッシュとTTL、データ保持、法務、コストを加えて定義する。前提は「当面は管理者1人（J-Quantsの規約のため）・月額はJ-Quants Lightの1,650円のみ・SLAなし」。「要確認」は技術検証や各社の最新の仕様で確かめる。

### 可用性

| 項目 | 要件 | 備考 |
|---|---|---|
| 稼働率の目標 | 月99% | Cloudflareに依存。無料プランにSLAはない |
| 計画停止 | なし（デプロイは無停止） |  |
| RPO（どこまで戻せればよいか） | 共通データ: 前営業日のバッチ時点。ユーザーデータ: 24時間以内 | D1のTime Travelで過去時点に復元（無料プランの保持日数は要確認） |
| RTO（復旧までの時間） | 24時間以内 |  |
| バッチ失敗時 | 営業日の当日中に自動で1回再実行。それでも失敗したら管理者にメール | 2営業日更新がなければ画面を警告色に（F8） |
| 縮退運転 | 取得失敗した銘柄は前回値を「古いデータ」として表示。AIが失敗した日はルールによる候補だけ表示 |  |
| 休場日 | JPXの休業日（土日祝・年末年始）はバッチを実行しない | 休業日リストは年1回更新 |

### 性能・拡張性

| 項目 | 要件 | 備考 |
|---|---|---|
| 画面の初回表示 | LCP 2.5秒以内（スマホ・4G） | Core Web Vitalsの「良い」基準 |
| API応答 | 95%が300ms以内 |  |
| 一覧の絞り込み | 全約3,800銘柄からの絞り込み結果を1秒以内に表示。サーバー側で並べ替え、50件ずつページ分割 | 絞り込みに使う列に索引 |
| バッチの時間 | 18:30開始、取得と指標計算は19:30まで、判定・AI・通知は20:30までに完了 | 技術検証で実測して見直す |
| 利用者数 | 想定10人、上限50人 | 招待制 |
| データ量 | 全上場約3,800銘柄×10年 | 株価履歴はR2、最新値と集計はD1 |
| 指標の追加 | コードの変更はdomainの計算と表の列追加だけで済む設計にする |  |

### キャッシュとTTL

| 対象 | TTL | 備考 |
|---|---|---|
| 銘柄一覧・状態API（サーバー側） | 24時間。キャッシュのキーに「データの版」（最新バッチのIDと終了時刻、EDINET 取り込みの時刻）を含め、バッチ完了から最大60秒で自動的に切り替える | データは1日1回しか変わらないため。D1 の読み取り（無料枠 500万行/日）を画面の操作で使い切らない。CloudflareのCache API |
| ブラウザ側（API） | Cache-Control: private, max-age=300 + ETag | ユーザー固有データはno-store |
| 画面の静的ファイル | ハッシュ付きのJS・CSSは1年（immutable）、index.htmlはno-cache | デプロイ直後に新版が届く |
| Clerkの公開鍵（JWKS） | 1時間。検証に失敗したら即時に取り直す | 鍵の入れ替えに備える |
| 許可リストの判定結果 | 1時間（`users.checked_at`）。Worker のメモリにも持つ | アクセスのたびに D1 を読まない |
| セッショントークン | Clerk標準（短命で自動更新） |  |
| ログイン状態の最大期間 | 7日（Clerkの設定。PropFolioと共通になる点に注意） | 要確認 |
| AIレコメンド | 当日分のみ表示 |  |

### データ保持と削除

| データ | 保持期間 |
|---|---|
| 株価・配当の履歴（R2） | 直近10年（古い分は順次削除） |
| 年次財務・配当方針（D1） | 直近10期 |
| J-Quantsの応答（R2、保存する場合） | 1年（R2のライフサイクルルールで自動削除） |
| AIレコメンド | 90日 |
| 通知履歴、バッチの実行履歴、ログイン記録 | 1年 |
| アプリのログ | Cloudflareの標準保持期間（要確認） |
| 退会したユーザーのデータ | 保有株・条件・通知は即時削除。ログイン記録は1年後に削除 |

### 運用・保守性

| 項目 | 要件 |
|---|---|
| 監視 | バッチの結果（件数・失敗数・所要時間）をbatch_runsに残し、管理画面で見る。失敗と無料枠の80%到達で管理者にメール |
| データ品質チェック | 前日比±50%超の株価、配当性向300%超、欠損率が5%超を「要確認」として管理画面に出す（株式分割の取り違えなどを検知） |
| ログ | 構造化ログ（JSON）。キー・メールアドレス・保有株は出さない |
| デプロイと切り戻し | mainへのマージでGitHub Actionsが`wrangler deploy`。不具合時は`wrangler rollback`で過去バージョンに戻す |
| インフラの変更 | wranglerコマンドで行い、作成したリソースは[03](03_system_architecture.md#作成済みのリソース)に記録する。本番への変更は事前に人が承認する |
| 品質チェック（CI） | cargo fmt・clippy・test、tsc・lint・ビルドをプルリクエストごとに実行。domainとusecaseの単体テストのカバレッジ80%以上 |
| 依存の更新 | Dependabotで月1回。cargo audit・npm auditをCIで実行 |
| ドキュメント | README（構成・セットアップ・キー名）、設計判断の記録（ADR）、この仕様書 |

### 移行性

| 項目 | 要件 |
|---|---|
| 初期データ投入 | 全銘柄の10年分を初回に一括取得。D1の書き込み上限（1日10万行）を超えないよう、履歴はR2に置き、D1へは数日に分けて入れる |
| テーブル定義の変更 | `batch-cli migrate`で適用。後方互換を保ち、列の削除は2段階で行う |
| 取得元の切り替え | J-Quantsが使えなくなったら adapter-batch の取得部分だけを差し替える（domain・usecase は変えない） |
| データの持ち出し | 保有株と条件をCSVで書き出せる |

### セキュリティ

| 項目 | 要件 |
|---|---|
| 認証 | Google SSOのみ（Clerk）。許可リスト制 |
| 認可 | ユーザー固有データは本人のみ。管理者はシークレットADMIN_NOTIFY_EMAILと一致するユーザーだけ。管理画面はサーバー側でも判定 |
| 通信 | HTTPSのみ。HSTSを有効化 |
| ブラウザの守り | CSP（自ドメインとClerkのみ許可）、X-Frame-Options: DENY、Referrer-Policy。APIはAuthorizationヘッダーのトークンで受け、CSRFを防ぐ |
| 入力検証 | すべてのAPIでサーバー側でも検証。SQLはプレースホルダーのみ |
| レート制限 | 1ユーザーあたり60回/分。超えたら429 |
| 内部エンドポイント | バッチ完了通知はHMAC署名と時刻（5分以内）で検証し、再送を拒否 |
| シークレット | 公開リポジトリに値を置かない（下の節）。年1回と漏洩の疑いがあるときに入れ替える |
| 個人情報 | 保存するのはClerkのユーザーID・メールアドレス・表示名・保有株・IPアドレス（ログイン記録）だけ。プライバシーポリシーを掲示 |

### システム環境・使いやすさ

| 項目 | 要件 |
|---|---|
| 対応ブラウザ | Chrome・Edge・Safari・Firefoxの最新2版、iOS Safari、Android Chrome |
| 画面幅 | 360px以上（スマホでは一覧をカード表示に切り替え） |
| アクセシビリティ | WCAG 2.2 AA相当（文字のコントラスト、キーボード操作、色だけに意味を持たせない） |
| 言語と表記 | 日本語のみ。時刻は日本時間、日付はYYYY/MM/DD、金額は円、比率は小数点以下2桁の% |

### 法務・コンプライアンス

| 項目 | 要件 |
|---|---|
| 投資助言に当たらないこと | 売り時は「利用者が自分で決めた条件の機械的な判定」、AIレコメンドは「一般的な情報提供」として表示し、免責を画面とメールに記載。有償化や一般公開する前には専門家に確認する |
| データの利用条件 | J-Quantsの規約により、取得データの配布と分析結果の継続的な第三者提供はしない（当面は管理者1人で使う）。J-QuantsとJPXのデータは出典を画面に表示する |
| AIの出力 | 根拠の数字と出典を併記し、AIの文章であることを明示 |

|---|---|

| 無料枠の監視 | D1の読み書き、Workers AI、R2の使用量が80%に達したら管理者にメール。超過時は課金せず、AIなど優先度の低い機能から止める |
