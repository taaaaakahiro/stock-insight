# 02 非機能要件

> 出典: Claude Docs「増配期待株ダッシュボード 要件定義」（rev 56, 2026-10-21）。その後の実装（v0.3.0 まで）に合わせて更新

各表の「状態」は v0.3.0 時点の実装。空欄は方針・前提で、実装の有無を問わないもの。

## 利用プランと上限

2026-10-22 から Cloudflare は Workers Paid（月$5）にした。CPU の上限は1回30秒に広がり、D1 の上限は1日単位ではなく月単位の枠になったので、無料プランで最大の壁だった「1回の実行あたりCPU 10ms」と「D1 の書き込み1日10万行」は気にしなくてよくなった。GitHub Actions は公開リポジトリなので、実行時間の費用も気にしない。数値は2026年10月時点で、細かい値は Cloudflare の料金ページで要確認。

| サービス | プランと上限 | このアプリでの使い方 |
|---|---|---|
| Workers（API・Cron） | Workers Paid。CPU は1回30秒（設定で延ばせる） | 画面の API、日次バッチの起動、21:00 の AIレコメンド |
| Workflows | Workers Paid に含まれる | 判定Workflow（未実装）で使う予定 |
| Workers AI | 1日10,000 Neurons まで無料、超えた分は従量課金 | 候補50銘柄の毎日のレコメンド（`@cf/meta/llama-3.3-70b-instruct-fp8-fast`、1日1回で約400 Neurons）なら無料の範囲に収まる |
| D1 | Workers Paid に含まれる枠（読み取り・書き込みとも月単位） | 一覧の絞り込みは全銘柄を読むので、画面の API はデータの版をキーに Cache API に置き、許可リストの確認も Worker のメモリに持つ（2026-10-22 に無料枠の読み取りを超えたため）。株価の履歴は1銘柄1行（`price_history`）なので、保存のたびに全銘柄分（約4,300行）を書き直す。量と時間を抑えるため、`sync-jq` の保存は基本1回（最後）のまま |
| R2 | 10GB、書き込み100万回/月まで無料 | J-Quants の応答（日付ごと）と EDINET の文章（銘柄・種類ごと）の置き場 |
| メール送信 | Cloudflare Email Service。任意の宛先に送るには有料プランが要る（要確認） | メール（未実装）は管理者だけに送る |
| GitHub Actions | 公開リポジトリは標準のランナーが無料。1ジョブ最大6時間 | 日次バッチ。J-Quants と EDINET を別のジョブで並列に動かす |

- **認証の安全性**: 本人確認はGoogle SSO（Clerk経由）だけで、アプリはパスワードを保存しない。すべてのAPIでセッショントークンと許可リストを確認する。ログイン記録は1年保存
- **データ分離**: ユーザー固有データの取得・更新は、リポジトリ層で必ずuser_idを条件に含める
- **表示速度**: 一覧は終端での初回表示1秒以内を目安。指標は事前計算済みの1表から読む
- **見やすさ**: PCとスマホの両方に対応。ダークモード対応。数字は右寄せ・桁を揃える。色は「割安=緑、割高=赤、警告=黄」だけに意味を持たせる
- **障害時**: 画面は前回のデータで表示し続ける。バッチ失敗の管理者へのメールは未実装（今は GitHub Actions の失敗通知と画面の警告色）
- **免責表示**: 「情報提供のみ。投資判断は自己責任」をフッターに記載（メールは未実装）

## 非機能要件一覧

IPA「非機能要求グレード」の6分類（可用性・性能・運用保守・移行・セキュリティ・環境）に、キャッシュとTTL、データ保持、法務、コストを加えて定義する。前提は「当面は管理者1人（J-Quantsの規約のため）・月額はJ-Quants Lightの1,650円と Workers Paid の月$5・SLAなし」。「要確認」は技術検証や各社の最新の仕様で確かめる。

### 可用性

| 項目 | 要件 | 備考・状態 |
|---|---|---|
| 稼働率の目標 | 月99% | Cloudflareに依存。無料プランにSLAはない |
| 計画停止 | なし（デプロイは無停止） |  |
| RPO（どこまで戻せればよいか） | 共通データ: 前営業日のバッチ時点。ユーザーデータ: 24時間以内 | D1のTime Travelで過去時点に復元（無料プランの保持日数は要確認） |
| RTO（復旧までの時間） | 24時間以内 |  |
| バッチ失敗時 | 時間切れで止まっても、次回は前回の続きから取り込む | 済み（`sync_state`）。当日中の自動再実行と管理者メールは未実装 |
| 縮退運転 | EDINET の取得が失敗しても一覧の更新は止めない。AIが失敗した日はルールによる候補だけ表示 | EDINET は済み（J-Quants とは別のジョブで並列に動く）。AI が失敗した日は保存せず、画面には前の日の結果が出る（ルールの候補だけを出すのは未実装） |
| 休場日 | 土日・祝日（内閣府の祝日CSV）・年末年始（12/31〜1/3）はバッチを実行しない | 済み（`batch-cli should-run`。祝日は起動時に毎回取得） |

### 性能・拡張性

| 項目 | 要件 | 備考・状態 |
|---|---|---|
| 画面の初回表示 | LCP 2.5秒以内（スマホ・4G） | Core Web Vitalsの「良い」基準 |
| API応答 | 95%が300ms以内 |  |
| 一覧の絞り込み | 全約4,200銘柄からの絞り込み結果を1秒以内に表示。サーバー側で並べ替え、50件ずつページ分割 | 済み。絞り込みに使う主な列に索引 |
| バッチの時間 | 18:30開始、毎日の取り込みと指標計算は19:30まで | 初回（過去5年分）は約1時間。判定・AI・通知（未実装）は20:30まで |
| 利用者数 | 当面は管理者1人（J-Quantsの規約）。将来の想定10人、上限50人 | 招待制（許可リスト） |
| データ量 | 全上場約4,200銘柄×5年 | 株価の終値は D1 の `price_history`（1銘柄1行）、J-Quants の全項目は R2 |
| 指標の追加 | コードの変更はdomainの計算と表の列追加だけで済む設計にする |  |

### キャッシュとTTL

| 対象 | TTL | 状態 |
|---|---|---|
| 一覧・配当方針・状態のAPI（サーバー側） | 24時間。キャッシュのキーに「アプリの版＋データの版」（最新バッチのIDと終了時刻、EDINET 取り込みの時刻）を含め、バッチ完了から最大60秒で自動的に切り替える。D1 の読み取り（無料枠 500万行/日）を画面の操作で使い切らないため | 済み（CloudflareのCache API） |
| 一覧・配当方針・状態のAPI（ブラウザ側） | `Cache-Control: private, max-age=300` ＋ 弱い ETag（変わっていなければ 304） | 済み |
| ユーザー固有データのAPI（`/api/me`・`/api/portfolio`）とエラー応答 | `no-store` | 済み |
| 画面の静的ファイル | ハッシュ付きのJS・CSSは1年（immutable）、それ以外（index.html など）はno-cache | 済み（`web/public/_headers`） |
| Clerkの公開鍵（JWKS） | 1時間。検証に失敗したら即時に取り直す | 済み |
| 許可リストの判定結果 | 1時間（`users.checked_at`）。Worker のメモリにも持ち、その間は D1 を読まない。Clerk に問い合わせられないときは前回の結果を使う | 済み |
| セッショントークン | Clerk標準（短命で自動更新） |  |
| ログイン状態の最大期間 | 7日（Clerkの設定。PropFolioと共通になる点に注意） | 要確認 |
| AIレコメンド | 最新日の分だけを表示。ブラウザ側 `private, max-age=300` | 済み |

### データ保持と削除

| データ | 保持期間 | 状態 |
|---|---|---|
| 株価の終値（D1 `price_history`） | 直近5年＋1か月（`domain::price_history::KEEP_DAYS`。利回りの過去5年比に使う） | 済み。v0.3.0 までは3年で切り詰めていたため、本番では一度取り直す（[07](07_deploy.md#株価の履歴を5年分に取り直す)） |
| 年次・四半期の財務（D1） | 取り込んだ分すべて（J-Quants Light の過去5年＋以後） | 削除は未実装 |
| J-Quantsの応答（R2 `jquants/`） | 1年（R2のライフサイクルルールで自動削除） | ルールは未設定 |
| EDINET の文章（R2 `edinet/`）と手がかり（D1 `edinet_docs`） | 銘柄・種類ごとに最新の1通だけ。新しい書類で上書きし、新しい有報で古くなった半期報告書と上場していない銘柄の分は消す | 済み |
| AIレコメンド（D1 `recommendations`） | 90日 | 削除は未実装 |
| 通知履歴、バッチの実行履歴、ログイン記録 | 1年 | 削除は未実装 |
| アプリのログ | Cloudflareの標準保持期間（要確認） |  |
| 退会したユーザーのデータ | ポートフォリオ・保有株・条件・通知は即時削除。ログイン記録は1年後に削除 | 未実装 |

### 運用・保守性

| 項目 | 要件 | 状態 |
|---|---|---|
| 監視 | バッチの結果（件数・失敗数・所要時間）をbatch_runsに残し、管理画面で見る。失敗と無料枠の80%到達で管理者にメール | batch_runs は済み。管理画面とメールは未実装 |
| データ品質チェック | 前日比±50%超の株価、配当性向300%超、欠損率が5%超を「要確認」として管理画面に出す（株式分割の取り違えなどを検知） | 未実装 |
| ログ | 構造化ログ（JSON）。キー・メールアドレス・保有株は出さない | キー・メールアドレスは出していない。JSON 化は未実装（Workers Observability は有効） |
| デプロイと切り戻し | `wrangler deploy` は承認フローに沿って手で行う（[07](07_deploy.md)）。不具合時は`wrangler rollback`で過去バージョンに戻す | CI からの自動デプロイは未設定 |
| インフラの変更 | wranglerコマンドで行い、作成したリソースは[03](03_system_architecture.md#作成済みのリソース)に記録する。本番への変更は事前に人が承認する |  |
| 品質チェック（CI） | cargo fmt・clippy（ネイティブと wasm32）・test、pnpm lint・typecheck・test・build をプルリクエストごとに実行 | 済み（`.github/workflows/ci.yml`）。カバレッジの計測は未実装 |
| 依存の更新 | Dependabotで月1回。cargo audit・npm auditをCIで実行 | 未実装 |
| ドキュメント | README（構成・セットアップ・キー名）、この仕様書 | 設計判断の記録（ADR）は未作成 |

### 移行性

| 項目 | 要件 | 状態 |
|---|---|---|
| 初期データ投入 | 初回だけ過去5年分を取り込む。保存は最後に1回にまとめ（全銘柄の履歴の書き直しを減らす）、時間切れなら次回は続きから | 済み |
| テーブル定義の変更 | `migrations/`の連番SQLを`batch-cli migrate`で適用（日次バッチが毎回最初に実行する）。後方互換を保ち、列の削除は2段階で行う | 済み |
| 取得元の切り替え | J-Quantsが使えなくなったら adapter-batch の取得部分だけを差し替える（domain・usecase は変えない） |  |
| データの持ち出し | ポートフォリオ・保有株と条件をCSVで書き出せる | 未実装 |

### セキュリティ

| 項目 | 要件 | 状態 |
|---|---|---|
| 認証 | Google SSOのみ（Clerk）。許可リスト制 | 済み |
| 認可 | ユーザー固有データは本人のみ。管理者はシークレットADMIN_NOTIFY_EMAILと一致するユーザーだけ。管理画面はサーバー側でも判定 | 本人のみ・管理者の判定は済み（管理画面は未実装） |
| 通信 | HTTPSのみ。HSTSを有効化 | 済み |

| 入力検証 | すべてのAPIでサーバー側でも検証。SQLはプレースホルダーのみ（列名は固定の列挙からだけ選ぶ） | 済み |
| レート制限 | 1ユーザーあたり60回/分。超えたら429 | 未実装 |
| 内部エンドポイント | バッチ完了通知はHMAC署名と時刻（5分以内）で検証し、再送を拒否 | 未実装（判定Workflowと一緒に作る） |

| 個人情報 | 保存するのはClerkのユーザーID・メールアドレス・表示名・ポートフォリオ・IPアドレスとブラウザ（ログイン記録）だけ。プライバシーポリシーを掲示 | プライバシーポリシーは未掲示 |

| 項目 | 要件 |
|---|---|

### 法務・コンプライアンス

| 項目 | 要件 |
|---|---|
| 投資助言に当たらないこと | 売り時は「利用者が自分で決めた条件、または固定の基準の機械的な判定」、AIレコメンドは「一般的な情報提供」として表示し、免責を画面（とメール）に記載。有償化や一般公開する前には専門家に確認する |
| データの利用条件 | J-Quantsの規約により、取得データの配布と分析結果の継続的な第三者提供はしない（当面は管理者1人で使う）。J-Quants・JPX・EDINETのデータは出典を画面に表示する |
| AIの出力 | 根拠の数字と出典を併記し、AIの文章であることを明示 |
