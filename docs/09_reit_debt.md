# 09 REIT の有利子負債・物件

REIT が金利の上昇にどれだけ影響を受けるかを見るために、有価証券報告書（EDINET）から借入金の明細と物件ごとの稼働率・賃料を読む。日次バッチ（`batch-cli sync-reit`）が D1 に保存し、一覧の REIT のタブと銘柄の詳細ページに出す。

AIの3軸評価・セクター動向は[REIT分析](17_reit_analysis.md)で扱う。以下は従来の借入・物件の取得と表示。

## 取得元と読み方

| 項目 | 有報での場所 | 形 | 読み方 |
|---|---|---|---|
| 短期・長期借入金、投資法人債の残高 | 貸借対照表 | XBRL の数値（`ix:nonFraction`） | 当期末（`CurrentYearInstant…`）の値。読めた明細の答え合わせに使う |
| 借入ごとの残高・利率・返済期限 | 附属明細表「借入金明細表」 | HTML の表 | 結合セルを展開し、見出しの言葉（当期末・利率・返済期限・借入先）で列を探す |
| 固定・変動 | 借入金明細表の注記、金融商品の注記 | 文章 | 注の番号ごとに「固定金利」「スワップ…固定」「変動金利」を判定して借入に付ける。「借入金は全て変動金利」「その他は全て固定」も拾う |
| 金利スワップの契約額 | デリバティブ取引の注記・附属明細表 | HTML の表 | どの借入か書かれていない分は「実質固定（額のみ）」 |
| 返済予定（1年以内〜5年超） | 金融商品の注記 | HTML の表 | 当期の表（最後に出てくるもの） |
| 物件ごとの面積・稼働率・賃料 | 「投資資産」「主要な不動産等の概要」 | HTML の表 | 見出しに賃貸可能面積と稼働率（または賃貸面積）がある表。推移表（第N期が3列以上）は除く |

書類は `GET /api/v2/documents/<docID>?type=1`（iXBRL の zip）。type=5 の CSV は表のタグが消えてセルの文字がつながり、3万字で切れるので使えない。

REIT の書類は、書類一覧（`documents.json`）で `secCode` が空。府令コード `030`・書類種別 `120`・提出者名に「投資法人」で拾い、証券コードは書類の表紙（`jpdei_cor:SecurityCodeDEI`）から読む。

精度の確認は `batch-cli reit-probe`（D1 に触れない）。

## 金利の内訳の区分

| 区分 | 意味 |
|---|---|
| 固定（明記） | 注記などで固定金利と書かれている |
| 実質固定（スワップ・借入ごと） | 変動金利だが金利スワップで固定と、借入ごとに書かれている |
| 実質固定（スワップ額のみ） | スワップの契約額のうち、どの借入か書かれていない分。記載なしの借入から差し引く（上限は記載なしの額） |
| 変動（明記） | 変動金利と書かれている |
| 記載なし | 上のどれでもない。固定か変動か分からない |
| 投資法人債 | ほぼ固定だが、明記はされていない |

固定・変動の手がかりは、注記のほかに表の中にもある。利率の欄（「固定金利 0.483%」「0.29655% (固定金利)」）や摘要の欄（「無担保 無保証 変動金利」）に書く銘柄があるので、借入の行のセルも見る。

## 解析結果の確認

借入明細の合計を貸借対照表と、物件明細を表の合計行と照合する。差や欠落は `checks` に保存する。非開示や書式の違いで取得できない値があり、「記載なし」を固定金利とみなさない。確認用CLIは `reit-probe`。

## 保存先

### 方針

- 一覧（REIT のタブ）で絞り込み・並べ替えに使う数字だけを D1 `reit_profile` に 1 銘柄 1 行で持つ
- 借入の明細・物件の一覧は、1銘柄1行のJSONとしてD1 `reit_detail` に保存する。API WorkerはD1から取得する
- 決算ごとの要約を D1 `reit_history` に 1 銘柄 1 期 1 行で持つ
- 用途（物流・ホテル・住宅…）は有報から機械的に決めにくいので、リポジトリの `data/reit_sectors.csv` に置く（新規上場時などに更新する）。バッチが毎回 `reit_profile.sector` に反映する

テーブルの定義は `migrations/0011_reit.sql`。

### D1 `reit_profile`（最新の有報、1 銘柄 1 行）

| 列 | 内容 |
|---|---|
| code | 証券コード（表紙の SecurityCodeDEI） |
| doc_id / submitted / period_end | 元の書類 |
| sector | office / logistics / residential / hotel / retail / healthcare / diversified / infra |
| short_loans / long_loans / bonds | BS の有利子負債（円） |
| rate_fixed / rate_swap_fixed / rate_swap_amount / rate_floating / rate_unknown | 金利の内訳（円）。投資法人債は bonds |
| swap_notional | 金利スワップの契約額 |
| avg_rate / avg_years | 借入の残高加重の平均利率（%）と平均残存年数 |
| reprice_1y | 1 年以内に金利が見直される額（下限）= 変動（明記）の全額 ＋ それ以外で1年以内に返済期限が来る借入 ＋ 1年以内に償還が来る投資法人債。変動借入は二重計上しない。金利が記載なしでも1年以内に返済期限が来る借入は含む |
| reprice_1y_max | 上の額 ＋ max(0, スワップ額のみの分を除いた記載なし額 − 1年以内に返済期限が来る記載なし借入額) |
| property_count / leasable_m2 / leased_m2 / occupancy | 物件の数・面積・面積加重の稼働率（%） |
| checks | 読み取りの確認（JSON: 借入 一致/端数/ずれ/明細なし、物件 一致/端数/ずれ/合計行なし/物件なし）。画面で「参考値」と出すかに使う |

同じ銘柄のもっと新しい期がすでにあれば上書きしない（`ON CONFLICT ... WHERE excluded.period_end >= reit_profile.period_end`）。古い書類から順に取り込むので、初回の取り込みで過去の期が最新を消すことはない。`reit_detail` も同じ。

### D1 `reit_detail`（最新の有報の明細、1 銘柄 1 行）

`body` は JSON: `loans`（借入先・残高・利率・返済期限・金利の種類）、`ladder`（返済予定の科目ごとの 6 区分）、`rate_notes`（金利の種類の判定に使った注記）、`properties`（物件番号・名称・面積・稼働率・年間賃料。非開示はその旨）。

### D1 `reit_history`（決算ごと、1 銘柄 1 期 1 行）

有利子負債、変動（明記）・記載なしの額、スワップの契約額、平均利率、物件数・面積・稼働率。

## API

- `GET /api/stocks?kind=reit` の行に `reit`（用途・変動の割合・記載なしの割合・1 年内の見直しの割合の下限と上限・平均利率・稼働率。比率は小数）を含む。並べ替えと範囲の絞り込みは `floating_ratio` / `unknown_ratio` / `reprice_ratio` / `reprice_max_ratio` / `avg_rate` / `occupancy`、用途は `reit_sector=logistics,hotel`
- `GET /api/stocks/:code/reit`: 要約・明細・推移。まだ取り込んでいない銘柄は 404
- サーバー側キャッシュの版（`DATA_VERSION`）に `sync_state.reit_listed_until` の更新時刻を含む

## 画面

- 一覧の REIT のタブ: 用途の絞り込み、銘柄名の下に用途、列に「変動金利」「金利の記載なし」「1 年内の金利見直し」「同（最大）」「平均利率」「稼働率」（説明は i のツールチップ）
- 詳細ページ（REIT）: 有利子負債・1 年内に見直される額・金利 +1% で増える年間の利息（幅で出す）・平均利率・平均残存年数・稼働率、金利の内訳の帯、返済・償還の予定、決算ごとの推移（2 期以上あるとき）、物件ごとの稼働率・賃料（稼働率の低い順など）、借入の明細

金利の内訳の色は、固定（青）・投資法人債（黄）・スワップ（水色）・変動（オレンジ）の順。記載なしは系列の色を使わず灰色の斜線。色だけに頼らないよう、帯の下の表に名前と額を出す。

## バッチ

`batch-cli sync-reit`（日次バッチの `reit` ジョブ。J-Quants・EDINET と並列）:

1. 前回の続き（`sync_state.reit_listed_until`）から今日までの書類一覧を読み、投資法人の有報を拾う（初回は過去 400 日分）
2. 古い書類から順に type=1 の zip を取り、読んで `reit_profile` / `reit_detail` / `reit_history` に書く
3. 用途の対応表を `reit_profile` に反映し、続きの日付を残す。時間切れなら取り込めた書類の提出日の前日までを済みとする

`--dry-run <file>` で D1 に触れずに SQL を書ける（`--from` が必要）。
