# 09 REIT の有利子負債・物件（設計案）

REIT が金利の上昇にどれだけ影響を受けるかを見るために、有価証券報告書（EDINET）から借入金の明細と物件ごとの稼働率・賃料を読む。**この文書は提案で、テーブルはまだ作っていない。**

## 取得元と読み方

| 項目 | 有報での場所 | 形 | 読み方 |
|---|---|---|---|
| 短期・長期借入金、投資法人債の残高 | 貸借対照表 | XBRL の数値（`ix:nonFraction`） | 当期末（`CurrentYearInstant…`）の値。読めた明細の答え合わせに使う |
| 借入ごとの残高・利率・返済期限 | 附属明細表「借入金明細表」 | HTML の表 | 結合セルを展開し、見出しの言葉（当期末・利率・返済期限・借入先）で列を探す |
| 固定・変動 | 借入金明細表の注記、金融商品の注記 | 文章 | 注の番号ごとに「固定金利」「スワップ…固定」「変動金利」を判定して借入に付ける。「借入金は全て変動金利」「その他は全て固定」も拾う |
| 金利スワップの契約額 | デリバティブ取引の注記・附属明細表 | HTML の表 | どの借入か書かれていない分は「実質固定（額のみ）」 |
| 返済予定（1年以内〜5年超） | 金融商品の注記 | HTML の表 | 当期の表（最後に出てくるもの） |
| 物件ごとの面積・稼働率・賃料 | 「投資資産」「主要な不動産等の概要」 | HTML の表 | 見出しに賃貸可能面積と稼働率（または賃貸面積）がある表。推移表（第N期が3列以上）は除く |

書類は `GET /api/v2/documents/<docID>?type=1`（iXBRL の zip）。type=5 の CSV は表のタグが消えてセルの文字がつながり、3万字で切れるので使えない。

REIT の書類は、書類一覧（`documents.json`）で `secCode` が空。府令コード `030`・書類種別 `120`・提出者名に「投資法人」で拾い、証券コードは書類の表紙（`jpdei_cor:SecurityCodeDEI`）から読む。

精度の確認は `batch-cli reit-probe`（D1 に触れない）。

## 金利の内訳の区分

| 区分 | 意味 |
|---|---|
| 固定（明記） | 注記などで固定金利と書かれている |
| 実質固定（スワップ・借入ごと） | 変動金利だが金利スワップで固定と、借入ごとに書かれている |
| 実質固定（スワップ額のみ） | スワップの契約額のうち、どの借入か書かれていない分。記載なしの借入から差し引く（上限は記載なしの額） |
| 変動（明記） | 変動金利と書かれている |
| 記載なし | 上のどれでもない。固定か変動か分からない |
| 投資法人債 | ほぼ固定だが、明記はされていない |

固定・変動の手がかりは、注記のほかに表の中にもある。利率の欄（「固定金利 0.483%」「0.29655% (固定金利)」）や摘要の欄（「無担保 無保証 変動金利」）に書く銘柄があるので、借入の行のセルも見る。

## 読み取りの精度（2026-10-22、`reit-probe`）

2026-04-04〜10-21 に提出された投資法人の有報 62 通（REIT 57・インフラファンド 5）。

| 項目 | 結果 |
|---|---|
| 借入金の合計と BS（短期＋長期） | 62 通すべて一致（うち 5 通は端数の差。百万円・千円未満の切り捨てが行の数だけ積もる。0.1% 以内） |
| 短期・長期の区分 | 61 通で BS と一致。1 通（日本プライムリアルティ）は短期の表の書き方が特殊で一部が区分なし |
| 借入ごとの利率・返済期限 | 9,356 件中、利率 9,327 件・返済期限 9,356 件 |
| 返済予定（1年以内〜5年超） | 62 通すべて |
| 金利スワップの契約額 | スワップのある 48 通 |
| 物件一覧と表の合計行（REIT 57 通） | 一致 44・端数 2・合計行なし 4（物件は読めている）・ずれ 4・物件なし 3 |
| 物件 | 4,310 件、うち稼働率 4,125 件・賃料 2,630 件（残りは「非開示」が多い） |

ずれの 4 通は、面積が「非開示」の物件の分だけ合計行より少ない（KDX など）。物件なしの 3 通（オリックス不動産・三井不動産アコモデーション・野村不動産マスターファンド）は、有報に物件ごとの稼働率を載せていない（ポートフォリオ全体の推移だけ）。

金利の種類が分かる割合（REIT 57 通。「記載なし」の割合の分布）:

| 記載なし | 0% | 25% 未満 | 25〜50% | 50〜75% | 75% 以上 |
|---|---|---|---|---|---|
| 銘柄数 | 10 | 9 | 8 | 10 | 20 |

記載なしの中央値は 57%。全額わかるのは日本ビルファンド・日本ホテル＆レジデンシャル・オリックス不動産・森トラストリート・サンケイリアルエステートなど 10 銘柄。残りは書類に書かれていないので、これ以上は読めない（決算説明資料にしか載っていない）。

読み取りで手当てしたこと（どれも実際の書類で崩れた）:

- 協調融資で 1 つの金額のセルが複数の借入先に縦にまたがる → 結合の続きのマスに印を付け、最初の行でだけ数える
- 最初の借入が「300」のように桁区切りのない額 → 見出しの行は「数値のセルがない行」で見分ける
- 「区分(借入先)」や colspan で借入先の見出しが複数の列にまたがる → 借入先らしい文字がいちばん多い列を使う
- 「1年内返済予定の長期借入金」を縦書きにして文字の順番が崩れる → 文字の集まりでも見分ける
- 1年内返済予定の長期借入金が銘柄独自の要素名（`LongTermLoansRepayableWithinOneYearCL`）
- 物件の表: 用途別の小計（「物流施設 64物件 計」「コアアセット中計(41物件)」）、底地の面積（「48,932.00 (土地)」）、「入居率」、同じ期の「時点」と「期間」の 2 列、物件が列に並ぶ縦横逆の表、面積だけの表と稼働率の表が分かれている

## テーブル案（提案）

### 方針

- 一覧（REIT のタブ）で絞り込み・並べ替えに使う数字だけを D1 に 1 銘柄 1 行で持つ。借入の明細・物件の一覧は R2 の JSON に置き、詳細の画面で読む（物件が数百件ある銘柄もあるので、D1 の読み取り枠を使わない）
- 推移を見るため、決算ごとの数字を D1 に 1 銘柄 1 期 1 行で持つ（REIT は年 2 回 × 約 60 銘柄なので小さい）。物件ごとの推移は R2 の決算ごとの JSON から作る
- 用途（物流・ホテル・住宅…）は有報から機械的には決めにくいので、リポジトリに対応表を置く（約 60 行。新規上場のときに PR で足す）

### D1 `reit_profile`（最新の有報、1 銘柄 1 行）

| 列 | 型 | 内容 |
|---|---|---|
| code | TEXT PK | 証券コード（表紙の SecurityCodeDEI） |
| doc_id / submitted / period_end | TEXT | 元の書類 |
| sector | TEXT | 用途（office / logistics / residential / hotel / retail / healthcare / diversified / infra）。対応表から |
| short_loans / long_loans / bonds | INTEGER | BS の有利子負債（円） |
| rate_fixed / rate_swap_fixed / rate_swap_amount / rate_floating / rate_unknown | INTEGER | 金利の内訳（円）。投資法人債は bonds |
| swap_notional | INTEGER | 金利スワップの契約額 |
| avg_rate | REAL | 借入の残高加重の平均利率（%） |
| avg_years | REAL | 借入の残高加重の平均残存年数 |
| reprice_1y | INTEGER | 1 年以内に金利が見直される額 = 変動（明記）＋ 1 年以内に返済・償還が来る固定（借り換えで新しい金利になる）。記載なしは含めない |
| reprice_1y_max | INTEGER | 上の額に記載なしを全部変動とみなして足した上限 |
| property_count / leasable_m2 / leased_m2 | INTEGER / REAL | 物件の数と面積 |
| occupancy | REAL | 面積加重の稼働率（%） |
| checks | TEXT | 読み取りの確認結果（JSON: 借入 一致/端数/ずれ、物件 一致/…）。画面で「参考値」と出すかの判断に使う |
| fetched_at | INTEGER | |

金利の感応度は画面で出す: **金利 +1% で年間の支払利息が増える額** = reprice_1y × 1%（下限）〜 reprice_1y_max × 1%（上限）。1 口あたり分配金に対する割合は、J-Quants の分配金と発行済投資口数から出す。

### D1 `reit_history`（決算ごと、1 銘柄 1 期 1 行）

| 列 | 型 | 内容 |
|---|---|---|
| code, period_end | TEXT, TEXT | PK |
| occupancy / leasable_m2 / property_count | | ポートフォリオの稼働率・面積・物件数 |
| loans_total / bonds / avg_rate / rate_floating / rate_unknown / swap_notional | | 有利子負債と金利の内訳 |

### R2

| キー | 中身 |
|---|---|
| `edinet/<コード>/reit.json.gz` | 最新の有報の借入の明細（借入先・残高・利率・返済期限・金利の種類）、返済予定、注記の手がかり、物件の一覧（面積・稼働率・賃料） |
| `edinet/<コード>/reit/<期末日>.json.gz` | 決算ごとの同じ中身。物件ごとの稼働率・賃料の推移はこれを並べて作る |

### 用途の対応表

`data/reit_sectors.csv`（コード, 用途, 備考）。総合型・複合型は diversified。インフラファンドは infra。

### バッチ

- `sync-edinet` の書類一覧（1 日 1 回の呼び出し）で REIT の有報も拾う（呼び出しは増えない）。まだ持っていない書類だけ type=1 の zip を取って読む
- 初回は過去の有報も取って推移を作る（EDINET の書類一覧で遡れる範囲。何年分にするかは要相談）
- 借入の合計が BS と「ずれ」の書類も保存はするが、checks に残して画面で参考値と出す
