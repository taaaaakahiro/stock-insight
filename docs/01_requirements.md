# 01 要件定義

> 出典: Claude Docs「増配期待株ダッシュボード 要件定義」（rev 56, 2026-10-21）

## 目的とユースケース

日本株に絞り、「割安で、増配が期待できる株」を一覧ですぐ見つけ、保有株の増配期待が崩れそうなときと売り時をメールで知らせる。運用費は株価・財務データ（J-Quants Light、月1,650円）だけに抑える。

| # | ユースケース | 主な操作 |
|---|---|---|
| UC1 | 割安で増配が期待できる株を探す | 指標を範囲で絞り込む一覧で、PBR・配当性向・DOE・配当利回り・連続増配年数・業種をひと目で比べる |
| UC2 | 1銘柄を深掘りする | 銘柄詳細で10年分の業績・配当の推移と、配当利回りの過去レンジに対する現在地を見る |
| UC3 | 保有株を管理する | 保有銘柄（株数・取得単価）を登録する。データはユーザーごとに分ける |
| UC4 | 増配期待の崩れを知る | 毎日のバッチ後、保有株が警告条件に当たれば画面に通知する（メールは管理者のみ） |
| UC5 | 売り時を知る | ユーザーが時価の指標で売り時の条件を指定し、当たれば画面に通知する（メールは管理者のみ） |
| UC6 | AIのおすすめを見る | バッチで取得したデータをCloudflareのAIがスクリーニングし、理由つきでおすすめ銘柄を出す |
| UC7 | データの鮮度を確かめる | 画面上で、いつ取得したデータかが常に分かる |

対象外: 売買の発注、リアルタイム株価、日本株以外、上場していない投資信託（公募投信。無料の公式 API がなく、スクレイピングもしないため）。

一覧は「株式」「REIT」「ETF」をタブで分ける。REIT（インフラファンド等を含む）と ETF・ETN（上場投資信託など）は JPX の上場銘柄一覧と J-Quants から株式と同じ方法で取り込み、価格・分配金利回り・過去10年の位置で比べる（財務の指標は株式だけ）。

## 機能要件

機能は画面上の「整形済みデータの表示」と「日次バッチ後の判定・通知」の2つに分かれる。画面側では重い計算をしない。

### F1 本人確認（Google SSO / Clerk）・ログイン記録・ユーザー管理

- ログインはGoogle SSOのみ。アプリ自前のID・パスワードは持たない
- 本人確認はPropFolioで使っているClerkを使い回す（採用条件は下の表）。Cloudflare Access（Googleのみ許可、無料50ユーザー）は、Clerkが使えない場合の代替案
- 画面にはGoogleのログインボタンだけを置く。Clerkのログイン方法はインスタンス単位（PropFolioと共通）のため、API Worker側でも「Googleアカウントでログインしたユーザー」以外を拒否する（セッショントークンにログイン方法を載せて判定）
- PropFolioの利用者がそのまま入れないよう、利用できる人を許可リスト（メールアドレス、またはClerkのユーザーメタデータに「stock-insight利用可」の印）で管理する
- API Workerは毎回、Clerkのセッショントークン（JWT）を公開鍵（JWKS）で検証し、ユーザーを特定する。検証できなければ拒否する
- 初回ログイン時にユーザーを自動作成。保存するのはClerkのユーザーID、メールアドレス（通知先を兼ねる）、表示名だけ
- ログアウトはClerkのsignOut。同じルートドメインでセッションを共有する場合、PropFolioからもログアウトされる
- ログイン記録: ClerkのWebhook（session.created）をAPI Workerで受け、署名を検証してから、ユーザー・メールアドレス・日時・IPアドレス・ブラウザをlogin_eventsに残す。許可リスト外の人が拒否された記録も残す。管理者は画面で一覧できる
- 保有株・売り時条件・保存した絞り込み条件・通知履歴はユーザーごとに分離する（すべてのクエリをuser_idで絞る）
- 銘柄データと指標は全ユーザー共通

| PropFolioのClerkの本番ドメイン | stock.insight.maa-un.comで使えるか | 費用 |
|---|---|---|
| maa-un.com配下（例: propfolio.maa-un.com） | 使える。Clerkは同じルートドメインのサブドメイン間でセッションを標準で共有する | 無料（Hobbyプラン、月間利用者数万人まで） |
| 別のドメイン | 「サテライトドメイン」が必要 | Proプラン＋追加料金（有料）。この場合は別のClerkアプリを無料で作るか、Cloudflare Accessにする |

出典: [Clerk サテライトドメイン](https://clerk.com/docs/guides/dashboard/dns-domains/satellite-domains)、[Clerk 料金の解説](https://clerk.com/articles/clerk-pricing-explained)

### F2 スクリーニング一覧

- 各指標を範囲（下限〜上限）で絞り込む: 株価、PBR、PER、配当利回り、配当性向、DOE、連続増配年数、営業利益率、自己資本比率、時価総額
- フラグで絞り込む: 業種（33業種、複数選択）、市場区分、規模区分（大型・中型・小型）、「直近5期に赤字なし」、「営業利益が増加傾向」、「減配なし」
- 列ごとに並べ替え。絞り込み条件に名前を付けて保存できる（例: 「バリュー×増配」）
- 各行に「割安 / 中立 / 割高」バッジを表示。配当利回りがその銘柄の過去10年のどの位置にあるか（パーセンタイル）で判定する
- 絞り込みは整形済みの指標表に対するSQLのWHERE句で行う

- 除外条件をユーザーごとに保存し、一覧を開いたときに常に適用できる（例: 「配当性向が50%以上は表示しない」「赤字企業は表示しない」「無配は表示しない」）。一覧の上部に「除外中: 配当性向≧50%」のようにチップで表示し、ワンクリックで一時解除できる

- 規模区分は一覧にバッジで表示し、マウスを乗せると「何を基準にした区分か」を説明する。区分はJPXが時価総額と流動性で決めるTOPIXの規模区分をそのまま使う。並べて時価総額（億円）も表示する

| 表示 | JPXの区分 | 目安 |
|---|---|---|
| 大型 | TOPIX Core30 + TOPIX Large70 | 時価総額と流動性が特に高い上位100銘柄 |
| 中型 | TOPIX Mid400 | 大型に次ぐ400銘柄 |
| 小型 | TOPIX Small 1 / Small 2 | 上記以外のTOPIX構成銘柄 |
| 区分なし | — | TOPIXに含まれない銘柄（グロース市場など） |

### F3 銘柄詳細

- 売上・営業利益・純利益・営業キャッシュフロー・1株配当・配当性向・DOEの年次推移（最大10年）
- 配当利回りの推移グラフに、過去レンジの上位20%（買い場）と下位20%（売り時）の帯を重ねる
- 配当方針（累進配当・DOE目標など）のAI要約と、その出典（有価証券報告書）
- 各データの取得日時と取得元

### F4 保有株と増配期待アラート

- 保有株を登録する（銘柄コード・株数・取得単価・メモ）。評価額・取得単価に対する利回り（YOC）を表示
- 毎日のバッチ後、次の警告条件を判定する（しきい値はユーザーが変更可、初期値を示す）

| 警告 | 判定条件（初期値） | 重さ |
|---|---|---|
| 減配 | 直近の配当実績が前年同期を下回った（配当履歴と有報・半期報告書の実績で判定） | 高 |
| 配当方針の変更 | 有報の配当方針から「累進配当」「DOE目標」が消えた（AIで前年と比較） | 高 |
| 赤字転落 | 最新期の営業利益または純利益がマイナス | 高 |
| 本業の弱体化 | 営業利益が2期連続で減少 | 中 |
| 配当余力の低下 | 配当性向が70%超 | 中 |
| 現金の不足 | 営業キャッシュフローがマイナス | 中 |

### F5 売り時条件（時価指標）

- ユーザーが銘柄ごと／全保有株共通で条件を作る。条件はAND/ORで組み合わせ可能
- 使える指標は時価で変わるものに限定: 株価、配当利回り、配当利回りパーセンタイル、PBR、PER、取得単価からの騰落率
- 演算子は >=、<=。例: 「配当利回り <= 2.5%」 OR 「PBR >= 1.5」
- 判定は日次バッチ後（平日）に1回。同じ条件では、一度当たったら外れるまで再通知しない

### F6 通知（画面は全員、メールは管理者のみ）

- 日次バッチ後、ユーザーごとの警告と売り時を画面の通知に出す。メールは管理者にだけ、管理者の保有株の警告・売り時とバッチの結果をまとめて1通送る。宛先はシークレット（ADMIN_NOTIFY_EMAIL）で設定し、画面からは変更できない（該当がなければ送らない）
- 本文には銘柄名、当たった条件、現在値、データ取得日、銘柄詳細へのリンク
- 画面に通知履歴を残す

### F7 AIレコメンド

- 日次バッチ後、その日の株価でルールにより候補を50銘柄程度に絞ってから、Workers AIに渡して上位10銘柄と理由を1〜2文で出させる
- 全銘柄をAIに渡さないのは、無料枠と精度のため。AIは「数字の計算」ではなく「説明と優先順位付け」に使う
- 有報の「配当政策」節から、累進配当の有無とDOE目標値を抽出するのにも使う（F3・F4で利用）
- 画面に「AIによる参考情報であり投資助言ではない」と明記

### F8 データ鮮度の表示

- 全画面のヘッダーに「株価: 2026/10/20終値（10/20 18:30取得）」「財務: 最新の有報提出日」の形で表示
- 直近のバッチが失敗した、または2営業日以上更新がない場合は警告色で表示

## データ要件

株価・財務は日本取引所グループ公式のJ-Quants API（Lightプラン、月1,650円、60件/分、過去5年）を使う。日付を指定すると全銘柄分をまとめて返すため、毎日の取り込みは数回の呼び出しで済む。株価は平日毎日、大引け後（18:30 JST）に当日分を取得し、財務は決算短信ベースのサマリーを開示の翌営業日に反映する。初回だけ過去5年分をまとめて取り込み、以後は前回の続きだけを取る。

### 取得元

| データ | 取得元 | 更新頻度 | 備考 |
|---|---|---|---|
| 銘柄マスタ（コード、名称、種類〔株式・REIT・ETF〕、33業種、市場区分、規模区分） | JPX「東証上場銘柄一覧」（xlsx、無料） | 日次バッチの最初に更新（JPX の更新は月次） | 公式。`batch-cli sync-master` |
| 株価（日次終値、過去5年） | J-Quants `/equities/bars/daily`（日付指定で全銘柄） | 日次（平日） | 公式。分割調整前の終値を使う（配当も調整前のため） |
| 年間配当（1株配当・1口分配金）と財務（売上・営業利益・純利益・営業CF・自己資本・EPS・BPS・配当性向） | J-Quants `/fins/summary`（本決算の行だけ） | 日次。直近3日分を毎回取り直す | 公式。決算短信ベースなので有報より早い。ETFは対象外 |
| 配当方針の文章（累進配当・非減配・増配・DOE・配当性向の目標） | EDINET API v2（金融庁、無料・APIキー必要）の有価証券報告書・半期報告書。XBRL を CSV にしたもの（type=5）から「配当政策」「経営方針」「経営者による分析」の文章だけを抜く | 日次。書類一覧は1日1回の呼び出しで全社分。銘柄・種類ごとに最新の1通だけ持つ | 有報は年1回、半期報告書も年1回（2024年4月に四半期報告書は廃止）。四半期の決算短信は TDnet でEDINETにはないので、数字（売上・利益の伸び）は J-Quants で出す。判定は言葉の有無だけで、抜いた文を画面で読めるようにする |

Yahoo Finance（非公式。利回りが異常値になる不具合があった）は使わない。EDINETは一度障害で外したが、配当方針の文章だけのために2026年10月に戻した（数字はJ-Quantsのまま）。J-Quantsの無料プランは12週間遅れのため当日の株価に使えず、Lightにした。対象は全上場銘柄（約4,200。株式・REIT・ETF）。IR BANKや株探のスクレイピングはしない。J-Quantsの規約で、取得したデータの配布と分析結果の継続提供は禁止されているため、当面は管理者1人で使う前提とする（複数人で使う前にJPXに確認する）。

### 取得日時の管理

- バッチの実行ごとに「開始・終了日時、対象銘柄数、成功数、失敗数、状態」を記録する
- 各データ行に「取得日時」「取得元」「基準日（株価なら終値の日、財務なら決算期と提出日）」を持つ
- 1銘柄の取得失敗でバッチ全体を止めず、前回の値を残して「古いデータ」と表示する

指標の計算式は [05 詳細設計](05_detailed_design.md#指標の定義) を参照。非機能要件は [02 非機能要件](02_non_functional_requirements.md) を参照。
