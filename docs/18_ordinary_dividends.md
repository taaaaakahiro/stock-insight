# J-QuantsとEDINETによる配当利回り

取得元はJ-QuantsとEDINETのみ。企業サイトを個別巡回する処理と手動の配当内訳ファイルは使用しない。

## 採用順序

1. 開示済みの最新対象年度の会社予想年間配当総額を使用する。特別・記念配当の内訳の有無によらず予想を優先し、予想総額から控除しない。明示的な0円予想も採用する。
2. 同じ対象年度では最新開示を採用する。例えば2026年10月時点の3月決算企業は2027年3月期予想を使い、後日開示された過年度の訂正予想で上書きしない。
3. 最新年度の予想未定の場合は最新実績を使用し、EDINETで年度・金額を照合できた特別・記念配当を差し引く。実績の内訳も不明なら実績合計を使用する。配当自体がない場合は利回りも不明。

配当利回り = 採用した年間1株配当 ÷ 株価。会社予想・実績の区別を表示する。過去の特別配当を来期の予想から引くことはしない。REIT・ETFも予想優先を維持する。

## バッチ処理

- `sync-jq`：株価、配当実績、会社予想を取得する。
- `sync-edinet`：有価証券報告書の「配当政策」から、当期の配当合計・普通配当・特別配当・記念配当が明記された文を抽出する。
- 旧EDINETデータは、抽出バージョンが未設定の有報を時間制限内で再取得する。文章を取得できたが内訳を抽出できなかった場合も処理済みにし、毎回取り直さない。
- EDINETの年度・合計額とJ-Quantsの実績が一致する場合だけ内訳を適用する。元の総額は保持する。
- 日次のJ-Quants・EDINET両ジョブ完了後に再計算し、新しい内訳を同日の指標に反映する。EDINETが失敗した場合もJ-Quants側の計算結果は残る。

配当内訳も元の配当と同じ株式分割係数で調整する。EDINET提出日より前の株価に対して、後から分かった内訳をさかのぼって適用しない。出典はEDINET書類URL、根拠の文は`edinet_docs.dividend_phrase`に保存する。

## 抽出できる範囲

「当期の期末配当金858円（普通配当198円、特別配当660円）」のような明示的な文を対象とする。普通配当と臨時配当の和が合計と一致することを検証する。期末の金額しか書かれていない場合は、J-Quantsの年間合計にも一致しなければ適用しない。

過年度・翌期・予想・株式分割が混在する文、合計が合わない文、相反する候補は採用しない。表だけに内訳がある場合、文脈が複数文に分かれる場合などは未確認となる。すべての会社の内訳を自動で確定できる仕組みではない。

通常配当を使った場合も、今後12か月に受け取れる金額を意味しない。配当性向や実績DOEは年間配当合計を使用する。

## 反映と確認

公開時は `0024_dividend_breakdowns.sql` を適用してからAPI・画面を配信する。既存の指標は `compute` で再計算し、EDINETの内訳は新しい `sync-edinet` 完了後の再計算で反映する。

検証はRustの抽出・実績切替・分割調整・提出日境界テスト、SQLiteでの年度・金額照合とオンライン/バッチ読取SQLの一致、Webの未確認表示テストで行う。実APIでの抽出率は未測定。
