| F4 保有株と警告 | 一部 | ポートフォリオ（☆で最大100銘柄を登録、売り時のサイン5種）。株数・取得単価・警告のしきい値は未実装 |
| F5 売り時条件 | 未実装 | 代わりにポートフォリオの固定のサイン（F4）を出す |

| F7 AIレコメンド | 済み | 平日21:00の Cron でルールにより候補50銘柄に絞り、Workers AI が上位10銘柄と理由を出す。画面の「AIレコメンド」タブ。配当方針は AI ではなく言葉の有無で判定（EDINET） |
| F8 データ鮮度 | ほぼ済み | ヘッダーに株価の日付と取得日時。失敗・2日以上更新なしで警告色。財務の日付は未表示 |
| 日次バッチ | 済み | Cron Trigger → GitHub Actions。JPX の銘柄マスタのあと、J-Quants（株価・財務・指標の計算）と EDINET（配当方針）を並列のジョブで取り込む |

## 用語

| 用語 | 意味 |
|---|---|
| DOE | 株主資本配当率（配当金総額 ÷ 自己資本）。このアプリでは簡易版（1株配当 ÷ BPS） |
| 利回りの過去5年比（パーセンタイル） | 現在の配当利回りが、その銘柄の過去5年の週次配当利回りのうち下から何%の位置か（J-Quants Light で取れるのが過去5年のため） |
| YOC | 取得単価に対する配当利回り（Yield on Cost）。取得単価を持つようになったら使う（未実装） |
| 有報 | 有価証券報告書 |
| 半期報告書 | 年1回の中間期の報告書。四半期報告書は2024年4月に廃止 |
| ポートフォリオ | ユーザーが☆で登録した銘柄の一覧。取得単価は持たず、売り時のサインだけを出す |
| 売り時のサイン | ポートフォリオの銘柄に出す5つの固定の判定（配当性向50%超・割高・増配停止・減益傾向・赤字あり） |
| 配当方針の手がかり | EDINET の有報・半期報告書の文章から拾った「累進配当」「非減配」「増配」「DOE」「配当性向の目標」の記述 |
| 日次バッチ | 平日18:30 JSTに起動する取得・指標計算の処理（GitHub Actions 上の Rust CLI `batch-cli`） |
| 判定Workflow | 日次バッチ完了後に動く、警告・売り時・通知の処理（Cloudflare Workflows。未実装）。AIレコメンドは先に API Worker の Cron で実装した |

## 決定事項と次のステップ

実装前に決めるべき点はすべて決まった。

- [x] ドメイン: maa-un.comのサブドメインだけを使う（stock.insight.maa-un.com）。PropFolioのClerkを無料のまま共用する
- [x] メール: 管理者だけの機能。宛先はシークレットで登録する
- [x] Cloudflare のプラン: 2026-10-22 から Workers Paid（月$5）。GitHub Actions は公開リポジトリなので実行時間の費用は気にしない
- [x] 対象銘柄: 全上場銘柄（株式・REIT・ETF）
- [x] 決算短信の速報: 対象外
- [x] 株価・財務の取得元: J-Quants Light（月1,650円）。Yahoo Financeは使わない。EDINETは配当方針の文章（有報・半期報告書の最新1通ずつ）だけに使う。規約により当面は管理者1人で使う
- [x] インフラ: リソースはwranglerコマンドで作成し、当面はCloudflare側で管理する（あとでmaaun-terraformにimportするかもしれない）。デプロイとシークレットもコマンド（wrangler・gh）で行う
