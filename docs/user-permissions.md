# 機能別・ユーザー区分別の権限仕様

現行のユーザー区分と操作可否を定義する。コードの実装状態を示し、本番への反映状態とは区別する。

## 1. ユーザー区分

| 区分 | APIの値 | 条件 | 利用範囲 |
|---|---|---|---|
| スーパーユーザー（管理者） | `superuser` | Google確認済みで、主メールアドレスが `ADMIN_NOTIFY_EMAIL` と一致 | 一般向け機能と、明示的に許可された管理操作 |
| 一般 | `general` | Google確認済みで、管理者以外、かつ Clerk の `public_metadata.stock_insight` が `true` | 閲覧と自分のデータの管理 |
| 未ログイン | なし | 有効なセッショントークンがない | ログイン画面のみ。保護されたAPIは利用不可 |
| 利用未許可 | なし | 認証済みだがGoogleの確認条件または許可リストの条件を満たさない | 利用不可の案内とログアウトのみ。保護されたAPIは利用不可 |

管理者以外を一般とすることは、すべてのGoogleユーザーに利用を開放することではない。利用許可の確認後に区分を決める。取得データの契約上の利用範囲は別途管理する。

スーパーユーザーにも、他人の個人データを閲覧・変更する特権は与えない。アプリのユーザー区分と、Clerk・GitHub・Cloudflareなど外部サービスの管理権限は別に扱う。

## 2. 現在利用できる機能

「可」はアプリで実行できる操作、「不可」は許可しない操作を表す。データの有無や処理の前提条件によっては、権限があっても結果を表示・生成できない。

| 機能 | 操作 | スーパーユーザー | 一般 | 対象・制約 |
|---|---|---|---|---|
| F1 本人確認 | 自分のユーザー情報・区分・権限を確認 | 可 | 可 | `/api/me`。他人の情報を取得するAPIはない |
| F1 セッション | ログアウト | 可 | 可 | 自分のセッション |
| F2 スクリーニング | 株式・REIT・ETFの一覧を閲覧 | 可 | 可 | 全ユーザー共通の銘柄データ |
| F2 スクリーニング | コード・名前の検索、指標・業種等の絞り込み | 可 | 可 | 実装済みの検索条件に限る |
| F2 スクリーニング | 並べ替え・ページ切り替え・条件リセット | 可 | 可 | 共通データの変更は伴わない |
| F2 スクリーニング | URLで検索条件を再現 | 可 | 可 | URLを開く側にもログイン・利用許可が必要 |
| F3 銘柄詳細 | 年次・四半期の業績、配当・株価・利回りの推移を閲覧 | 可 | 可 | 取り込み済みのデータを表示 |
| F3 配当方針 | EDINETの配当方針の記述・提出日等を閲覧 | 可 | 可 | 有報・半期報告書の取得済み情報 |
| F3 REIT詳細 | 借入金の金利構成・返済期限、物件・稼働率等を閲覧 | 可 | 可 | REITの取得済み情報 |
| F4 ポートフォリオ | 登録銘柄・指標・固定の売り時サインを閲覧 | 可 | 可 | 本人のポートフォリオのみ |
| F4 ポートフォリオ | 銘柄を登録 | 可 | 可 | 本人のポートフォリオに最大100銘柄 |
| F4 ポートフォリオ | 銘柄の登録を解除 | 可 | 可 | 本人のポートフォリオのみ |
| F4 ポートフォリオ | 他人の登録銘柄を閲覧・登録・解除 | 不可 | 不可 | 管理者にも代理操作を許可しない |
| F7 AIレコメンド | 最新の結果・順位・理由・指標・モデル・作成日時を閲覧 | 可 | 可 | 結果は全ユーザー共通 |
| F7 AIレコメンド | 作り直しを実行 | 可 | 不可 | 管理者専用。成功時は対象日の共通結果を置き換える |
| F8 データ鮮度 | 株価・財務の日付、取得日時、直近バッチの状態を確認 | 可 | 可 | ヘッダーと `/api/status`。詳細な運用管理画面とは別 |
| 注目テーマ | 管理画面を開く | 可 | 不可 | 現在のタブは管理者専用 |
| 注目テーマ | 一覧・詳細・該当銘柄をAPIで取得 | 可 | 可 | 閲覧APIは両区分に許可。一般向けタブは提供しない |
| 注目テーマ | テーマ名・キーワードを登録 | 可 | 不可 | 有報の事業内容と照合し、共通のテーマ株を保存 |
| 注目テーマ | テーマ名・キーワードを編集して再照合 | 可 | 不可 | 全ユーザー共通のテーマを更新 |
| 注目テーマ | テーマを削除 | 可 | 不可 | 共通のテーマと対応づけを削除 |
| 共通データ | 株価・財務・指標をアプリから直接編集・削除 | 不可 | 不可 | ユーザー向けの編集APIはない |

未ログイン・利用未許可のユーザーは、上表の保護されたデータ・機能を利用できない。ログイン画面の表示とGoogle認証の開始は未ログインでも可能。

## 3. 未実装の機能と予定する権限

この表の「許可予定」は要件上の権限であり、現在は操作できない。「未定」は仕様確定が必要な項目を表す。

| 機能 | 操作 | スーパーユーザー | 一般 | 現在の状態・範囲 |
|---|---|---|---|---|
| F1 管理 | ログイン記録の一覧を閲覧 | 許可予定 | 不可 | 記録の保存は実装済み。管理画面・取得APIは未実装 |
| F1 管理 | アプリ内で利用者一覧・利用許可・区分を管理 | 未定 | 不可 | アプリ内の管理機能はない。現在の運用方法は第4節 |
| F2 保存条件 | 名前付き検索条件・除外条件を保存、変更、削除 | 許可予定 | 許可予定 | 本人の条件のみ。URLによる再現とは別機能 |
| F4 保有株 | 株数・取得単価・メモの登録、変更、削除 | 許可予定 | 許可予定 | 本人の保有株のみ。現在は銘柄コードの登録のみ |
| F4 警告 | 警告のしきい値を設定・変更 | 許可予定 | 許可予定 | 本人の設定のみ。現在の固定サインは変更不可 |
| F5 売り時条件 | 条件の作成・変更・削除 | 許可予定 | 許可予定 | 本人の銘柄別／全保有株共通の条件 |
| F6 画面通知 | 通知・通知履歴を閲覧 | 許可予定 | 許可予定 | 本人に対する通知のみ |
| F6 メール通知 | 警告・売り時・バッチ結果のメールを受信 | 許可予定 | 不可 | 管理者本人の保有株と運用結果。宛先は設定済みの管理者アドレス |
| F6 メール通知 | アプリ画面からメール宛先を変更 | 不可 | 不可 | 宛先はシークレットで管理する仕様 |
| 設定 | 保有株・条件をCSVで書き出す | 許可予定 | 許可予定 | 本人のデータのみ |
| 運用管理 | バッチ履歴・品質チェック・使用量を管理画面で確認 | 許可予定 | 不可 | 一般にも見える直近のデータ鮮度とは別機能 |
| 退会 | アプリ内から退会・個人データを削除 | 未定 | 未定 | 操作画面・API・実行権限・削除範囲は未確定 |

未実装機能の内容は [未実装要件](15_unimplemented_requirements.md) に従う。未定の機能に権限を付与する際は、この仕様とサーバー側の認可を同時に更新する。

## 4. 自動処理と外部サービスでの運用

以下はアプリのユーザーが画面から実行する機能ではない。スーパーユーザーでログインしても、外部サービスの操作権限を自動的に取得することはない。

| 処理・操作 | 実行主体／必要な権限 | アプリからの手動操作 |
|---|---|---|
| 日次データ取得・指標計算 | CronとGitHub Actionsのサービス認証 | 両区分とも不可 |
| 日次AIレコメンド生成 | API WorkerのCronとAIバインディング | 自動処理。管理者の手動再生成は別API |
| 利用許可の付与・解除 | Clerkを管理できる運用者が `public_metadata.stock_insight` を設定 | 両区分とも不可 |
| 管理者アドレスの設定・変更 | Workerのシークレットを管理できる運用者 | 両区分とも不可 |
| バッチの手動実行、デプロイ、DB変更 | GitHub・Cloudflare等の対象操作権限を持つ運用者 | 両区分とも不可 |

## 5. APIの認可仕様

すべての `/api/*` で有効なBearerトークンと利用許可を確認する。画面のボタン非表示だけで制限を済ませず、サーバー側で権限とデータ所有者を確認する。

| メソッド・パス | スーパーユーザー | 一般 | 認可・対象 |
|---|---|---|---|
| `GET /api/me` | 可 | 可 | 自分のユーザー情報のみ |
| `GET /api/stocks` | 可 | 可 | 共通のスクリーニング結果 |
| `GET /api/stocks/:code` | 可 | 可 | 共通の銘柄詳細 |
| `GET /api/stocks/:code/edinet` | 可 | 可 | 共通の配当方針 |
| `GET /api/stocks/:code/reit` | 可 | 可 | 共通のREIT詳細 |
| `GET /api/status` | 可 | 可 | 直近バッチ・データ鮮度 |
| `GET /api/portfolio` | 可 | 可 | 認証済みユーザーIDで絞り込む |
| `PUT /api/portfolio/:code` | 可 | 可 | 認証済みユーザーIDを登録先とする |
| `DELETE /api/portfolio/:code` | 可 | 可 | 認証済みユーザーIDを解除対象とする |
| `GET /api/recommendations` | 可 | 可 | 共通の最新結果 |
| `POST /api/recommendations/regenerate` | 可 | 不可（403） | `RegenerateRecommendations` を検証 |
| `GET /api/themes` | 可 | 可 | 共通のテーマ一覧 |
| `GET /api/themes/:id` | 可 | 可 | テーマ詳細・該当銘柄 |
| `POST /api/themes` | 可 | 不可（403） | `ManageThemes` を検証 |
| `PUT /api/themes/:id` | 可 | 不可（403） | `ManageThemes` を検証 |
| `DELETE /api/themes/:id` | 可 | 不可（403） | `ManageThemes` を検証 |

### 判定の一元化

- `domain::access::Role` は `Superuser` / `General` の2値とする。
- `Permission::ManageThemes`（登録・編集・削除）と `Permission::RegenerateRecommendations` はスーパーユーザーのみ許可する。
- `AuthUser::can` をAPI側の管理操作の判定に使う。
- `/api/me` は `role`、`permissions.manage_themes`、`permissions.regenerate_recommendations` を返す。`is_admin` は旧クライアントとの互換用に残す。
- 画面は `role` で区分を表示し、サーバーが返した `permissions` に従って管理操作を表示する。テーマ管理タブは `manage_themes` が真の場合のみ表示する。
- ポートフォリオの対象ユーザーはクライアントから指定させず、認証結果のIDを使う。

### 認証情報の更新と拒否

Google確認済みの条件は、主メールアドレスと同じアドレスのGoogleアカウントが連携・確認済みであること。管理者アドレスとの比較は前後の空白を除き、大文字小文字を区別しない。

許可・管理者の判定結果は `users` に保存し、通常は1時間ごとにClerkへ確認し直す。Clerkへの問い合わせ失敗時は保存済みの判定を使う。したがって、許可解除・管理者変更の即時反映は保証しない。保存済み情報がなく問い合わせにも失敗した場合は503とする。

| 状態 | 応答 |
|---|---|
| トークンなし・不正・期限切れ | 401 |
| Google確認条件を満たさない／利用未許可 | 403 |
| 一般ユーザーによる管理者専用操作 | 403 |
| 存在しないAPI（利用許可済みユーザーからの要求） | 404 |
| 認証設定不足・認証情報を取得できない | 503 |

### AIレコメンドの作り直し

1. AIや保存先を利用する前に管理権限を確認し、一般は403で拒否する。
2. 最新バッチが成功しており、株価日付と候補銘柄が存在する場合に生成する。バッチが当日終了したかどうか、同じ日付の結果が存在するかどうかでは拒否しない。
3. 前提条件を満たさない場合は409。AI生成・出力検証・保存の失敗は500とする。
4. AI出力を検証した後、対象日の既存結果の削除と新しい結果の保存を同じトランザクションで行う。失敗時は既存結果を維持する。
5. 成功時は全ユーザーが参照する共通結果が更新される。画面は再取得する。結果取得APIと再生成APIは `no-store` とする。

## 6. 受け入れ基準

- スーパーユーザーと一般の両方が、共通データと自分のポートフォリオを利用できる。
- 一般ユーザーには再生成ボタンを表示せず、APIを直接呼んでも403となり、AI実行・データ更新が起きない。
- スーパーユーザーでも他人のポートフォリオを閲覧・変更できない。
- 未ログイン・利用未許可のユーザーには保護されたデータを返さない。
- 管理者の再生成が失敗しても保存済みの結果を失わない。
- テーマ登録・編集・削除は、一般ユーザーによる直接API呼び出しも403で拒否する。閲覧APIは両区分に許可する。
- 未実装・未定の機能を、権限一覧や画面上で実装済みと扱わない。

この節は検証すべき仕様を示すもので、全項目の自動テスト実装・本番検証済みを意味しない。
