# 権限仕様

## ユーザー区分

| 区分 | 条件 |
|---|---|
| 管理者 `superuser` | Google確認済みで、主メールアドレスが `ADMIN_NOTIFY_EMAIL` と一致 |
| 一般 `general` | Google確認済みで、管理者以外、かつClerkの `public_metadata.stock_insight=true` |
| 未ログイン・利用未許可 | 保護されたデータ・機能は利用不可 |

管理者でもGoogle確認は必要。メールの比較は前後空白と大文字小文字を無視する。認証の更新間隔と障害時の扱いは[認証仕様](05_detailed_design.md)を参照。

## 操作の可否

| 操作 | 管理者 | 一般 | 範囲 |
|---|---|---|---|
| 銘柄検索・詳細・配当方針・REIT分析・データ鮮度の閲覧 | 可 | 可 | 共通データ |
| レコメンド・履歴・成績の閲覧 | 可 | 可 | 共通結果 |
| ポートフォリオの閲覧・登録・解除・取得日の設定 | 可 | 可 | 本人のみ、最大100銘柄 |
| 他人のポートフォリオの閲覧・変更 | 不可 | 不可 | 管理者にも代理権限なし |
| レコメンドの作り直し | 可 | 不可 | 共通結果を更新。生成条件は[AI仕様](12_recommendations_and_themes.md) |
| テーマの閲覧API・レコメンド内のテーマ表示 | 可 | 可 | 共通データ |
| テーマ管理画面・登録・編集・削除 | 可 | 不可 | 共通テーマを変更 |
| 自分のユーザー情報確認・ログアウト | 可 | 可 | 本人のみ |
| アプリからの株価・財務・指標の直接編集 | 不可 | 不可 | 編集APIなし |

## サーバー側の制御

全 `/api/*` でBearerトークンと利用許可を確認する。一般ユーザーによる管理操作は403、未認証は401。画面のボタン非表示だけに依存しない。

管理操作は `AuthUser::can` で確認する。`Permission::ManageThemes` と `Permission::RegenerateRecommendations` は管理者のみ。`/api/me` は `role` と `permissions` を返し、画面もこの値で表示を制御する。`is_admin` は旧クライアントとの互換用。

ポートフォリオの対象ユーザーIDは認証結果から決め、入力では受け取らない。API一覧は[API仕様](10_api.md)を参照。

## 基盤の運用権限

利用許可の付与・解除はClerk、バッチ起動・設定はGitHub、デプロイ・DB変更はCloudflareなどの操作権限が必要。アプリの管理者権限だけでは実行できない。REIT分析の手動生成ボタンはない。

実装: [権限定義](../crates/domain/src/access.rs)、[認証](../crates/usecase/src/auth.rs)、[API](../crates/api-worker/src/lib.rs)。
