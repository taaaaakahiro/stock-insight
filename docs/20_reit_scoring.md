# J-REIT評価・ランキング・比較 v1.0

評価設定は **`jreit-v1`**。株式の評価・AIレコメンド・[REITの3軸AI分析](17_reit_analysis.md)とは別の定量評価。増配の持続性、物件の稼ぐ力、財務・金利耐性、含み益、割安度を比較する。将来の価格・分配金や換金可能額を保証しない。査定の基準日と、価格・財務開示の時点はそれぞれ表示する。

## 画面

- 「J-REITランキング」では総合、増配・分配金持続性、収益成長、財務・金利安全性、含み益・NAV、割安度を切り替える。用途、確定利回り下限、実質変動金利比率とLTVの上限、充足率下限、評価基準日で絞り込める。全体順位と同用途内順位は絞り込みで再計算しない。
- 確定12か月利回りと予想年利回りは別列。予想が12か月分に満たない場合は「部分予想」と表示し、年利回りは出さない。順位のない暫定評価も一覧に載せる。
- 銘柄詳細は総合点、7カテゴリの取得点／満点と未採点配点、採点根拠、決算期ごとの確定・正常化DPUと1口FFOの履歴、利上げ試算を表示する。過去5年の成長率に使う起点を含め、最大6時点。強み・弱みは各指標の中央値からの寄与差で選び、元データを開ける。
- 比較は同じ公開版から最大5銘柄。総合点、確定年間DPU、確定・正常化DPUの5年CAGR、正常化DPU、同一物件の年間NOI、1口FFO、含み益／純資産、NAV倍率、LTV、実質変動金利比率、支払利息／NOI、100bpストレスを並べる。

## 採点

比較対象は評価日に上場済みの [JPX J-REIT銘柄一覧](https://www.jpx.co.jp/equities/products/reits/issues/index.html)。REITと同じ区分に保存されるインフラファンド等は含めない。用途は `data/reit_sectors.csv`。用途不明の銘柄も全体の採点対象とする。

| カテゴリ | 満点 | 指標（配点・方向） |
|---|---:|---|
| 分配金成長・持続性 | 25 | 正常化年間DPU 5年CAGR（12↑）、継続分配原資カバー率（8↑）、売却益等依存率（5↓） |
| 保有物件の収益力 | 20 | 同一物件NOI 3年CAGR（10↑）、1口FFO 5年CAGR（7↑）、稼働率（3↑） |
| 財務健全性・金利耐性 | 20 | 比較可能LTV（5↓）、実質変動金利比率（6↓）、24か月満期集中率（3↓）、利払い余力（3↑）、金利+1.0%pt負担率（3↓） |
| 不動産の含み益・NAV | 15 | 含み益／純資産（7↑）、1口NAV 3年CAGR（5↑）、物件売却流動性（3↑、評価保留） |
| 割安度 | 10 | P/NAV（6↓）、価格／年間1口FFO（4↓） |
| 資産規模・分散・質 | 5 | NOI実効分散指数（3↑）、最大物件NOI依存率（2↓） |
| スポンサー・運用能力 | 5 | スポンサーの信用力（3↑、評価保留）、資本配分実績（2↑、評価保留） |

有効な入力が8銘柄以上ある指標について、全体での順位を0〜100のパーセンタイルにする。同値は平均順位で、↓は向きを反転する。取得点は「配点 × パーセンタイル ÷ 100」。カテゴリは取得点を足し、未採点分の配点も表示する。総合点は「取得点合計 ÷ 採点可能配点 × 100」。採点可能配点がゼロなら総合点は `null`。条件別の順位には対象カテゴリの取得点を採点可能配点で割った得点率を用いる。各順位は丸め前の得点（降順）、充足率（降順）、証券コード（昇順）で決める。

充足率は採点可能配点を満点100で割ったもの。80%未満、10暦日超の価格または価格未取得、270暦日超の確定分配・財務期末、確定12か月の決算期不足、確認できる財務開示がない場合は暫定評価とし、どの順位にも含めない。80%以上90%未満は欠損ありと表示。出典なし、未確認、推計、要再確認の値は採点しない。明示的な実測ゼロは有効。EDINET一覧に訂正・取下げ情報がある開示は確認が済むまで採点しない。

LTVが55%超、実質変動金利比率が50%超、利払い余力が2倍未満、100bpストレスが正常化年間分配額の10%超なら別に警告を出す。

## 指標と入力

- **DPU**：直近の確定開示の決算期末まで、途切れのない12か月を合計する。年2回の2,500円＋2,600円は5,100円、10万円なら5.1%。支払月は使わない。同一期の開示を日時、リビジョンIDの順で選び、投資口の分割・併合を反映する。利回りに使う開示の締切は価格日（JSTの日付単位）。会社予想は将来12か月の対象期だけを集計し、同じ期は最新の開示を1件だけ使う。
- **正常化DPU**：確認できた売却益由来分配とその他一時分配を合計し、確定DPUから差し引く。利益超過分配の一時・継続の種別を区別し、全額控除しない。一時要因の内訳不明は欠損。売却益等依存率は一時分配金÷確定年間DPU。原資カバー率は正常化年間AFFO÷正常化年間分配額。AFFOは継続収益から維持修繕CAPEX等を控除した金額で、補足入力の出典・算定条件を確認する。
- **NOI・FFO**：同一物件NOIは両時点で同じ保有物件の年額を比較。物件取得・売却で変わる全体NOIを流用しない。FFOは純利益＋不動産減価償却費−物件売却益＋物件売却損。各決算期のFFOを期中平均口数で割り、分割調整した12か月分を合計する。検証済みの年間1口FFOを直接取り込むこともできる。実効分散指数は `1/Σ(各物件のNOI構成比²)`、集中率は最大の構成比。
- **NAV**：含み益＝鑑定評価額−簿価。NAV＝簿価純資産＋鑑定含み益−必要な調整。EDINETの自動取得は純資産と鑑定含み益による簡易NAV。調整項目がある場合は出典で定義を示した入力を用いる。P/NAVは価格÷同じ口数基準の1口NAV。鑑定額は即時の売却価格ではない。
- **財務**：同一期末の有利子負債÷総資産を比較可能LTVとする。発行体公表LTVは別項目。実質変動金利比率はヘッジ後の変動残高÷有利子負債。24か月満期集中率は期末から24か月以内に満期となる残高÷有利子負債。利払い余力は調整後年間EBITDA÷年間支払利息。支払利息／NOIは年間の利息とNOIで計算する。
- **ストレス**：有利子負債×実質変動比率×上昇幅（+0.5/1.0/2.0%pt）÷正常化年間分配額。借換え込みは、即時変動分に含まれない固定負債のうち、12・24か月以内の借換え対象額へ同じ金利差を掛けた負担をそれぞれ加える。年末の年額換算であり、期中発生時期・税務・ヘッジの再契約・物件入替え・賃料の増減を織り込まない。

自動取得は、[J-Quantsの日足](https://jpx-jquants.com/ja/spec/eq-bars-daily)の価格・分割、[財務サマリー](https://jpx-jquants.com/ja/spec/fin-summary)の確定分配・予想、EDINET有報の同一期末の貸借対照表・借入表・稼働率・鑑定額／簿価・1口NAV。金利区分不明、金額のみのスワップ、金利区分を確認できない投資法人債を自動的に固定扱いしない。TDnet予想PDFは表と数値を確認できるページが一意の場合に採用し、開示IDとページを保存する。取得手順は[バッチ運用](13_batch_operations.md#reit-の分配予想pdf)を参照。

EDINET有報から当期純利益、物件売却損益、賃貸事業の減価償却費、期中平均投資口数、利息、賃貸事業全体のNOIと調整後EBITDAも取得する。非連結の会計範囲と期首・期末を確認し、注記の金額単位はiXBRLの数値と照合する。利息はキャッシュフロー計算書の支払利息調整項目。NOIは賃貸事業収益合計−同費用合計＋賃貸事業の減価償却費。調整後EBITDAは営業利益＋賃貸事業の減価償却費−物件売却益＋物件売却損。全体NOIは利息との比率の計算に使う。FFO、NOI、利息、EBITDAの年額は同じ会計範囲の連続した12か月分から計算する。

一時分配、正常化AFFO・分配総額、同一物件NOI、NOI分散、債券・ヘッジの精査データは、原資料で確認した値を `import-reit-observations --from-file <JSON配列>` で取り込む。自動取得項目だけでの理論上の最大充足率は49%。正式な総合順位には補足データと各指標8銘柄以上が必要。実際の充足率は本番のバッチ結果で確認する。

### 補足入力の契約

[マイグレーション](../migrations/0027_reit_scoring.sql)が保存列の正本。JSONでは `normalization_flags` と `quality_flags` は文字列配列。期間末と対象決算期末は同日、`as_of_date` は原数値の投資口基準日（その他は観測日）。日付は `YYYY-MM-DD`、開示日時はJSTの `YYYY-MM-DDTHH:MM:SS` または日付。出典はHTTPSの公開資料。PDFのページを特定できる場合は1始まりで `source_page` に記録する。欠損は `metric_value: null`。同じ開示IDの再取込では行を増やさず、訂正は新しい `revision_id` を割り当てる。推計 (`estimated`) や `quality_flags` がある値は採点に使わない。

| 項目 | キー（単位） |
|---|---|
| 期別実績・予想・一時分配 | `actual_dpu`, `forecast_dpu`, `one_off_dpu`（JPY/unit） |
| FFO・NAVの1口額 | `ffo_per_unit`, `nav_per_unit`（JPY/unit） |
| 決算期FFOの原数値 | `net_income`, `depreciation`, `property_sale_gain`, `property_sale_loss`（JPY）、`ffo_units`（units） |
| 決算期の収益・支払利息 | `period_noi`, `period_interest`, `period_ebitda`（JPY）。期首・期末を必須とし、年額に合算する |
| 年間の分配原資・収益・支払利息 | `normalized_affo`, `normalized_payout`, `annual_noi`, `annual_interest`, `annual_ebitda`（JPY） |
| 同一物件の年間NOI | `same_noi`, `same_noi_base`（JPY）。同じ資料・リビジョン・期末に紐付け、両方の `period_start` に3年前の基準期末を指定 |
| 期末残高・評価額 | `debt`, `assets`, `net_assets`, `property_fair_value`, `property_book_value`, `swap_notional`（JPY） |
| 固定負債の満期予定 | `fixed_maturing_12m`, `fixed_maturing_24m`（JPY、累計） |
| 財務・稼働・集中 | `floating_ratio`, `maturity_24m`, `issuer_ltv`, `occupancy`, `noi_concentration`（ratio）、`remaining_years`（years）、`noi_diversification`（index） |

## 公開と検証

日次取得の `sync-jq → compute_all → compute → indicators_latest` は既存指標を更新する。定量評価は日次成功後の独立した `reit-batch` で、REIT資料同期後に全銘柄を読み、まとめて計算する。定量評価はAI分析の有効化を必要としない。補足入力の取り込み後などは `compute-reit-scores` で再実行する。

基準日・設定版・入力を含むスナップショットのハッシュをキーとし、同じ入力の再実行で版を増やさない。評価日時、対象数、採点根拠、欠損理由、元データを保存する。銘柄行と内訳行がそろってから公開状態を1文で更新する。中断中の版は非公開で、公開済みの版と `indicators_latest` を維持する。過去版のAPIは公開済みのスナップショットを読む。現在の銘柄一覧を使った過去日へのさかのぼり採点は行わない。

検証は、半期2期・単一期不足・期末と開示日の区別・訂正・分割・一時分配・同一物件NOI・ピア数と同点・実測ゼロ・金利ストレス・比較上限・SQLiteの公開ガードを対象とする。流動性・スポンサー・資本配分のルーブリック、横断データの追加自動取得と、実績でのバックテスト・配点再検証は今後の作業。
