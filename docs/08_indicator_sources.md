# 08 指標の取得元と計算式

一覧・詳細に出す各指標が、どの API のどの項目から、どう計算されているかの一覧。取得元は J-Quants API V2（Light プラン）、EDINET API v2（配当方針の文章だけ）と JPX の上場銘柄一覧。Yahoo Finance は使わない。

## 取得元の API

| API | エンドポイント | 呼び方 | 保存先 |
|---|---|---|---|
| 株価四本値 | `GET /v2/equities/bars/daily?date=YYYY-MM-DD` | 日付指定で全上場銘柄。ページ分割（`pagination_key`）をたどる | 全項目: R2 `jquants/bars/<日付>.json.gz`。終値だけ: D1 `price_history`（1銘柄1行、`YYYYMMDD,終値;…`）。株式分割・併合: D1 `splits`（`AdjFactor` が 1 でない日） |
| 財務情報サマリー | `GET /v2/fins/summary?date=YYYY-MM-DD` | 日付指定でその日に開示された全銘柄。同上 | 全項目: R2 `jquants/fins/<日付>.json.gz`。本決算（`CurPerType=FY`）: D1 `financials_annual`。四半期（1Q/2Q/3Q）: D1 `financials_quarterly`。配当予想: D1 `dividend_forecasts`（開示1件1行） |
| 上場銘柄一覧 | JPX `data_j.xlsx` | 日次バッチの最初に全件 | D1 `stocks`（名称・種類・市場・33業種・規模区分） |
| 祝日 | 内閣府 `syukujitsu.csv` | バッチ起動時 | 保存しない（休場日の判定のみ） |
| 書類一覧 | EDINET `GET /api/v2/documents.json?date=YYYY-MM-DD&type=2` | 日付指定で全社分（1日1回）。有報（`docTypeCode=120`）と半期報告書（`160`）で、CSV があり取下げでないものだけ。訂正（130・170）は使わない | 保存しない（取る書類を選ぶだけ） |
| 書類 | EDINET `GET /api/v2/documents/<docID>?type=5` | 銘柄・種類ごとに最新の1通だけ、まだ持っていないものを取る | 文章: R2 `edinet/<コード>/annual.json.gz`・`semiannual.json.gz`（新しい書類で上書き）。手がかり: D1 `edinet_docs`（1銘柄・1種類1行） |

取り込みは `batch-cli sync-jq`。初回だけ過去5年分、以後は前回の続き（`sync_state.jq_synced_until`）。財務は直近3日分を毎回取り直す。

EDINET は `batch-cli sync-edinet`。初回は過去400日分の書類一覧（有報は年1回なので、提出の遅い会社も含めて1年強）、以後は前回の続き（`sync_state.edinet_listed_until`）。今日の一覧はバッチの後にも書類が増えうるので、続きの位置は前日までしか進めず、翌日もう一度読む（取得済みの書類は飛ばす）。日次バッチの中では J-Quants と別のジョブで並列に動く。API キーは URL に載せずヘッダー（`Ocp-Apim-Subscription-Key`。`Subscription-Key` ヘッダーは 401 になる）で渡す。古い書類の扱い:

- 同じ銘柄・種類の新しい書類が出たら、D1 の行と R2 のファイルを上書きする（古い書類は残らない）
- 同じ事業年度かそれより後の有報が出たら、その半期報告書は消す（初回の取り込みでは最初から取らない）。EDINET の `periodEnd` は半期報告書でも事業年度の末日なので、有報の `periodEnd` ≥ 半期報告書の `periodEnd` で比べる
- 書類一覧には、その日に縦覧の状態などが変わった過去の書類も載るので、その日に提出された書類だけを使う
- 上場していない銘柄（最新の JPX 一覧にない）の書類は消す
- R2 から消すキーはバッチが `raw/edinet-delete.txt` に書き、`edinet` ジョブの最後に `wrangler r2 object delete` で消す

## 項目の対応

### 株価（`/equities/bars/daily`）

| 使う項目 | 意味 | 用途 |
|---|---|---|
| `Code` | 5桁コード（末尾0）。4桁に直す（`130A0` → `130A`）。末尾が0でない優先株は除く | 銘柄の特定 |
| `Date` | 日付 | 履歴の日付 |
| `C` | 終値（**分割調整前**） | 株価、利回り、PBR、PER。保存は調整前のままで、計算のときに `AdjFactor` で最新の株数の基準にそろえる |
| `AdjFactor` | 調整係数。1:2 の分割なら権利落ち日の行に 0.5（分割のない日は 1.0） | 1 でない日を D1 `splits` に残す（下の「株式分割の扱い」） |

`AdjC`（調整済み終値）は使わない（過去の値が分割のたびに書き換わり、1銘柄1行の履歴と合わないため。同じことを `AdjFactor` で計算のときに行う）。約定がない日（`C` が null）は履歴に入れない。

### 株式分割の扱い（`domain/src/split.rs`、`usecase/src/daily.rs` の `build_inputs`）

終値は分割調整前、配当・EPS・BPS は開示した時点の1株当たりなので、そのまま割ると、分割の後から次の本決算の開示までの間だけ「分割後の株価 ÷ 分割前の配当」になり、利回りが分割の比率の分だけ高く出る（例: 2026-09-29 に分割した東京海上は、分割前の配当218円 ÷ 分割後の株価で約39%になっていた）。そこで計算のときに、すべてを最新の株数の基準にそろえる。

| 値 | そろえ方 |
|---|---|
| 終値 | その日より後に権利落ちした分割の `AdjFactor` をすべて掛ける（権利落ち日の終値はもう分割後） |
| EPS・BPS | 開示した日（`disclosed`。なければ期末＋45日）より後に権利落ちした分割の `AdjFactor` をすべて掛ける（期末の後・開示の前の分割は、期首に行ったものとして計算し直して開示される） |
| 1株配当（実績） | 期末の1週間前より後に権利落ちした分割の `AdjFactor` をすべて掛ける。配当は期末の株主に払うので期末の株数の基準で、期末の翌日に効力が出る分割（権利落ちは期末の数営業日前）は開示の前でも入っていない |
| 1株配当の会社予想 | 予想を開示した日と、対象の期末の1週間前の早いほうより後に権利落ちした分割の `AdjFactor` をすべて掛ける |

例: SPK（7466）は 2026-03-30 に1:2の分割（効力は 4/1）。2026-05-08 に開示した 2026/03 期の配当73円は分割前の株の値で、EPS 133.35円は分割後に直した値。配当だけ 36.5円に直すので、利回りは 73円 ÷ 1,405円 の5.2%ではなく2.6%、配当性向は55%ではなく27%になる。

これで利回り・利回りの過去5年比・PBR・PER・配当性向・DOE・連続増配年数・詳細ページの推移が、分割をまたいでもそろう。D1 の `price_history` と財務の値は調整前のまま保存する。分割の記録は `sync-jq` が日足を読むたびに残すので、過去の分割は株価の取り直し（`--refill-prices`）で集める。

### 財務（`/fins/summary`）

| 使う項目 | 意味 | D1 の列 |
|---|---|---|
| `Code`, `DiscNo`, `DiscDate` | 銘柄、開示番号、開示日 | `code`, `doc_id`, `disclosed` |
| `CurPerType` | `1Q`/`2Q`/`3Q`/`FY`（4Q・5Q の変則決算は対象外） | `period_type`（四半期のみ） |
| `CurPerEn`, `CurFYEn` | 当期間の終了日、当事業年度の終了日 | `period_end`, `fiscal_year_end` |
| `Sales` / `NCSales` | 売上高（連結 / 非連結。連結がなければ非連結） | `net_sales` |
| `OP` / `NCOP` | 営業利益 | `operating_income` |
| `OdP` / `NCOdP` | 経常利益 | `ordinary_income` |
| `NP` / `NCNP` | 当期純利益 | `net_income` |
| `ShEq` / `Eq` / `NCShEq` / `NCEq` | 自己資本（なければ純資産） | `equity` |
| `EPS` / `NCEPS` | 1株当たり当期純利益 | `eps` |
| `BPS` / `NCBPS` | 1株当たり純資産 | `bps` |
| `DivAnn` / `DivUnit` | 1株当たり年間配当実績 / 1口当たり分配金（REIT） | `dps` |
| `FDivAnn` / `FDivUnit` | 当事業年度の年間配当予想 / 予想分配金（REIT）。1Q〜3Q の決算短信と予想の修正の行で使う | `dividend_forecasts.dps` |
| `NxFDivAnn` / `NxFDivUnit` | 翌事業年度の年間配当予想 / 予想分配金（REIT）。本決算の行で使う | `dividend_forecasts.dps` |
| `DocType` | 開示書類の種別。`…ForecastRevision`（配当予想・業績予想・分配予想・利益予想の修正）は実績の数字がないので、年次・四半期の財務には入れず、配当予想だけ取る。配当予想が空の修正（業績予想だけの修正）は取らない。PR #29 より前に年次として取り込んだ修正の行は D1 に残っているので、指標・詳細ページでは期末のほかに数字が1つもない年次の行を飛ばし、最新の本決算にも5期の表にも入れない | — |
| `CFO` | 営業活動によるキャッシュ・フロー | `operating_cf` |

四半期の行は期首からの累計値。四半期単独の値は計算時に差分で出す（Q1 = 1Q、Q2 = 2Q − 1Q、Q3 = 3Q − 2Q、Q4 = FY − 3Q）。前の四半期の行がない場合は不明（None）。

ETF は財務情報サマリーに載らないため、価格だけで利回りは出ない。

## 指標の計算式（`domain/src/indicators.rs`, `analysis.rs`）

| 指標 | 計算 | 元データ |
|---|---|---|
| 株価 | 最新の終値 | `C` |
| 1株配当（利回りに使う配当） | その時点でいちばん新しい開示（決算短信・配当予想の修正）の会社予想。その開示に予想がなければ（未定・非開示）、その時点で開示済みの最新の実績 | `FDivAnn`・`NxFDivAnn`（予想）, `DivAnn`（実績）。どれも開示日 `DiscDate` から有効 |
| 配当利回り | 上の1株配当 ÷ 終値。予想か実績かは `indicators_latest.dividend_basis`（`forecast` / `actual`）に残し、画面の1株配当の横に出す | 上と同じ, `C` |
| 利回りの過去5年比（パーセンタイル） | 週1点（5営業日ごと）の過去5年の利回りの中で、今の利回りが下から何%か。同じ値は半分だけ数える。52点未満なら出さない。80%以上で `cheap`、20%以下で `expensive`。過去の各時点の利回りも同じ決め方（その時点で最新の予想、なければ実績）で出す。`dividend_forecasts` は予想を取り始めた日（2026-10-19）以降と、`refill_forecasts` で読み直した期間（既定は直近1年）しかないので、それより前は実績になる | 上と同じ |
| PBR | 終値 ÷ BPS（最新の本決算）。BPS が 0 以下なら出さない | `C`, `BPS` |
| PER | 終値 ÷ EPS（最新の本決算）。EPS が 0 以下（赤字）なら出さない | `C`, `EPS` |
| 配当性向 | 1株配当の実績 ÷ EPS（予想ではなく最新の本決算） | `DivAnn`, `EPS` |
| DOE（簡易） | 1株配当の実績 ÷ BPS（同上） | `DivAnn`, `BPS` |
| DOE（予想） | 利回りが会社予想の配当のときだけ、配当利回り × PBR（= 予想の1株配当 ÷ BPS。分割の基準は PBR でそろう）。API で計算し、D1 には持たない | 上の利回り, PBR |
| DOE の余裕（`doe_margin`） | 比べる DOE − 有報の DOE の下限。比べる DOE は利回りが会社予想なら DOE（予想）、実績なら DOE（簡易）。マイナスは下限の方針より配当が少ない | 上の DOE, `edinet_docs.doe_floor` |
| 配当性向（予想） | 利回りが会社予想の配当のときだけ、配当利回り × PER（= 予想の1株配当 ÷ 直近の本決算の EPS）。赤字（PER なし）なら出さない。API で計算し、D1 には持たない | 上の利回り, PER |
| 方針との乖離（`policy_gap`） | 有報の DOE・配当性向の下限・目標と、比べる値（会社予想があれば予想、なければ実績）の差を「方針どおりに払えば配当が何 % 増えるか」（方針の値 ÷ 今の値 − 1）で出す。下限を割っているものを目標に届かないものより重く見て、同じ段なら余地の大きいほうを1つ返す（`basis` = `doe_floor` / `doe_goal` / `payout_floor` / `payout_goal`）。今の値が 0（無配）なら比べない。方針がないか満たしていれば null。API で計算し（`domain::dividend_policy`）、D1 には持たない。AI レコメンドの評価に使う | 上の DOE・配当性向, `edinet_docs` の下限・目標 |
| 営業利益率 | 営業利益 ÷ 売上高（最新の本決算） | `OP`, `Sales` |
| 連続増配年数 | 1株配当が前期を上回った回数を新しい期から数えた連続数。直近5期で数えるので最大4。2期なければ出さない | `DivAnn` × 5期 |
| 減配（`dividend_cut`） | 直近の本決算の1株配当の実績が前期の実績より少ない、または利回りに使う配当が会社予想でその予想が直近の実績より少ない（無配予想を含む）。どれも分割をそろえた後の値で比べ、据え置き（分割の調整の端数を含む）は減配にしない。比べる配当がなければ NULL。ポートフォリオの参考の売りサイン「減配」に使う | `DivAnn` × 2期, `FDivAnn`・`NxFDivAnn` |
| 5年連続で配当あり | 直近5期すべて 1株配当 > 0。5期なければ不明 | `DivAnn` × 5期 |
| 通期で赤字なし | 直近5期の純利益と営業利益（なければ経常利益）がすべてプラス | `NP`, `OP`（`OdP`） × 5期 |
| 営業利益の増加傾向 | 直近5期の営業利益（なければ経常利益）の最小二乗法の傾きがプラス（3期以上） | `OP`（`OdP`） × 5期 |
| 四半期で赤字なし | 直近20四半期の四半期単独の純利益・営業利益がすべてプラス。判定できる四半期が4未満なら不明 | 四半期の累計値の差分 |
| バリュー株 | PBR ≤ 1.0 かつ 0 < PER ≤ 15（基準は `analysis.rs` の `VALUE_PBR_MAX`・`VALUE_PER_MAX`） | PBR, PER |
| 売上の伸び・営業利益の伸び | 直近の期（1Q〜FY の期首からの累計）と、1年前の同じ期の累計の比 − 1（前年同期比）。前年の値がないか 0 以下なら出さない | `Sales`, `OP`（四半期の行と本決算の行） |
| 直近四半期の営業利益・純利益の伸び（`op_growth_q`・`net_growth_q`） | 営業利益が分かる直近の四半期単独の値（累計の差分）と、前年の同じ四半期の単独の値の比 − 1。前年の値がないか 0 以下なら出さない | `OP`, `NP`（四半期の累計の差分） |
| 直近4四半期の営業利益の伸び（`op_growth_ttm`） | 直近4四半期の単独の営業利益の合計 ÷ その前の4四半期の合計 − 1。8四半期すべて営業利益が分かり、期末の間隔が 600〜680日のときだけ（四半期が抜けていれば出さない） | `OP` × 8四半期 |
| 利益が一過性の疑い（`profit_one_off`） | 純利益の伸びが営業利益の伸びを 30 ポイント以上上回る（特別利益で膨らんでいる）、または直近の四半期は増益なのに直近4四半期の合計では前年を下回る。直近四半期の営業利益の伸びが出なければ NULL。一覧のバッジ「一過性?」と AI レコメンドの評価に使う（`analysis::latest_quarter`） | 上の3つ |

比率は小数で保存し（0.035 = 3.5%）、画面で % にする。

### 配当方針の手がかり（EDINET、`domain/src/disclosure.rs`）

有報・半期報告書の CSV（`XBRL_TO_CSV/jpcrp*.csv`、UTF-16LE の TSV）から、要素名が次で始まる `…TextBlock` の文章だけを取り出し、タグを除いて全角英数字を半角にする。

| 項目 | 要素名（`jpcrp_cor:`） |
|---|---|
| 配当政策 | `DividendPolicyTextBlock` |
| 経営方針、経営環境及び対処すべき課題等 | `BusinessPolicyBusinessEnvironmentIssuesToAddressEtcTextBlock` |
| 経営者による財政状態、経営成績及びキャッシュ・フローの状況の分析 | `ManagementAnalysisOfFinancialPosition…TextBlock` |

文（「。」区切り）ごとに次の言葉を探す。判定は言葉の有無だけなので、当てはまった文（最大5つ、各160文字まで）を `edinet_docs.phrases` に残し、画面で読めるようにする。

| D1 の列 | 言葉 |
|---|---|
| `progressive_dividend` | 累進配当、累進的な配当、累進的に |
| `no_dividend_cut` | 減配しない、減配を行わない、減配は行わない、減配を行わず、減配せず、非減配、維持または増配 など |
| `dividend_raise` | 増配 |
| `doe_target` | DOE、株主資本配当率、純資産配当率、自己資本配当率 |
| `doe_floor`・`doe_goal`・`doe_phrase` | DOE の言葉の後ろ40文字以内（配当性向・総還元・ROE などが出てきたらそこまで）の「3.5%」など。下は続きの説明 |
| `payout_floor`・`payout_goal`・`payout_phrase` | 「配当性向」の後ろ30文字以内（DOE・総還元・ROE や次の「配当性向」が出てきたらそこまで）の「30%」など。下限・目標の分け方は DOE と同じ。100%を超える値は捨てる |
| `payout_target` | 古い列。`payout_floor`（なければ `payout_goal`）と同じ値を入れ続ける |

DOE の下限と目標（`doe_floor`・`doe_goal`、比率は小数）は、DOE の言葉を含む文から次の順で決める。

1. 文に「特別配当」「記念配当」「実績」「となりました」「でした」があれば拾わない（方針ではない数字）
2. 「下限」「最低」「下回らない」「確保」があれば下限
3. 「目標」「目途」「目処」「目安」「目指す」「目線」があれば目標（「目標4%以上」は目標）
4. 「以上」があれば下限（「DOE 3%以上を基本方針」）
5. 「程度」「水準」「方針」「基本」「基準」があれば目標
6. どれもなければ拾わない（「DOE は3.5%となります」のような当期の値）

数字は「2.5%から3.5%へ」なら新しいほう、「3〜4%」なら下限の数字、「従来の3.5%から」のように新しい値がなければ拾わない。20%を超える値は読み違いとして捨てる。1通の中で文ごとに違う値（従来の計画と新しい計画）があれば大きいほうを取り、下限（なければ目標）を拾った文を `doe_phrase` に残す。一覧・詳細では、有報と半期報告書のうち値が書かれた新しい書類の値を使う。

この仕組みより前に取り込んだ書類は数字を持っていないので、`daily-batch` を `refetch_doe=true` で一度流して取り直す（DOE に触れていて下限も目標もない書類と、配当性向の目標（古い列）があるのに下限・目標に分けていない書類だけ。数百通）。「事業の内容」（`business_text`。注目テーマの照合用）も同じく、`refetch_business=true` で持っていない有報を取り直す（数千通あるので、時間切れまで進めて残りは次回）。

一覧の「累進配当・非減配の方針」の絞り込み（`dividend_policy=1`）とバッジは、有報か半期報告書のどちらかで `progressive_dividend` か `no_dividend_cut` が 1 の銘柄。バッジを押すと `/api/stocks/:code/edinet` から該当の文を読み込んで出す。

## AIレコメンド（F7）の候補・評価と使うモデル

日次バッチが成功した日の 21:00 JST（Cron `0 12 * * 1-5`）に、API Worker が `recommendations` に1日10行を書く。同じ日（`price_date`）の結果があれば作り直さない。候補の絞り込み・3段階の評価・順位はすべてルール（コード）で決め、AI には理由の文章だけを書かせる（数字の計算も優先順位付けもさせない）。

| 段階 | 内容 | 場所 |
|---|---|---|
| 候補の絞り込み（ルール） | 種類が株式で、配当利回りが分かっていて8%未満（`MAX_YIELD`。それ以上は特別配当や株価の急落で一時的に高く見えていることが多いので外す。2026-10-22 の本番では 10.4% の銘柄が1位になった）、保有していれば売りサインになる銘柄（配当性向50%超・PBR1.5倍超。`portfolio::PAYOUT_WARN`・`PBR_WARN`）と減配した銘柄（`dividend_cut`）を除き、バリュー株（PBR ≤ 1.0 かつ 0 < PER ≤ 15）または「5年連続で配当あり かつ 通期で赤字なし」 | `domain/src/recommend.rs`（`Candidate::is_eligible`）、SQL は `adapter-cf/src/query.rs` |
| 3段階の評価（ルール） | 材料は3つ。**乖離が大きい** = 配当方針との乖離（`policy_gap`）が下限割れ、または増配の余地 20% 以上（`STRONG_UPSIDE`）。**業績の質** = 通期で赤字がなく、一過性の疑い（`profit_one_off`）がなく、直近四半期の営業利益が前年同期比プラスか増益傾向。**割安** = バリュー株か利回りの過去5年比で割安。`strong`（強く推奨）= 乖離が大きい ＋ 業績の質 ＋ 割安。`recommend`（推奨）= 業績の質 ＋ 増配の根拠（乖離がある・2年以上の連続増配・累進配当の方針）。それ以外は `watch`（注目） | `Candidate::grade` |
| 順位（ルール） | 評価の高い順 → 注目テーマに当たる銘柄を先 → 下限割れを先 → 増配の余地の大きい順 → 満たす条件（バリュー・5年配当・通期黒字・四半期黒字・増益傾向）の多い順 → 利回りの高い順 → コード順。上位10銘柄（`PICK_COUNT`）だけを AI に渡す。テーマは評価を変えない（流行りだけで強く推奨にはしない） | `select_candidates` / `select_picks` |
| 注目テーマ | 管理者が「注目テーマ」タブでテーマ名と言葉（例: 半導体、パワー半導体、SiC）を登録する（`themes`）。保存のたびに Worker が、有報の「事業の内容」の文（`edinet_docs.business_text`。`DescriptionOfBusinessTextBlock` の先頭3000文字）に言葉が含まれる銘柄を `instr` で探して `stock_themes` を作り直す（部分一致。言葉は事業の内容と同じ整形で全角英数字を半角にする）。全員が一覧と当たった銘柄を見られる。AI には「注目テーマ」としてテーマ名を渡し、一言触れさせる | `domain/src/theme.rs`、`usecase/src/themes.rs`、`adapter-cf/src/d1_themes.rs`、`/api/themes` |
| AI への依頼 | 選んだ10銘柄を順位・評価つきで JSON で渡し、銘柄ごとの理由（1〜3文）を JSON Schema（`response_format`）で返させる。AI に値の良し悪しを判断させると「PBR 1.20倍と低い」のような誤りが出るため、各銘柄は「コード・銘柄名・業種・配当利回り・順位・評価」と、こちらで判定した文だけを渡す: **評価の決め手**（方針との乖離を値つきで。例: 「有報で DOE 3.5% を下限とする方針だが、今の実績の配当では DOE 2.8%（…方針どおりなら配当は +25.0% 増える）」）、**良い点**（値と「なぜ良いか」をつけた短い文。利回りの過去5年比が上位20%以内、PBR 1倍以下、PER 15倍以下、連続増配、累進配当・減配しない方針、配当性向40%以下、直近四半期の営業利益の伸び（なければ累計の伸び）、直近4四半期合計の伸び、売上高の伸び、増益傾向、5年配当、通期・四半期で5年黒字）、**注意**（一過性の疑いの中身、減配）、**配当方針の原文**（有報・半期報告書から DOE・配当性向の数字を拾った文。`edinet_docs.doe_phrase`・`payout_phrase`。選んだ10銘柄の分だけ読む）、**注目テーマ**（当たっているテーマ名）。指示文では、決め手を最初に値つきで書く・良い点から1〜2個を自然な日本語にする・書かれていない評価を足さない・注意は最後に短く・銘柄名から書き始めない・渡した銘柄すべてに渡した順で返す、を求める | `adapter-cf/src/recommend.rs` |
| モデル | Workers AI `@cf/meta/llama-3.3-70b-instruct-fp8-fast`（JSON モードに対応したテキスト生成モデル。1日1回・10銘柄で無料枠に収まる。`llama-3.1-8b-instruct-fp8` は JSON Schema に対応しておらず、`@cf/meta/llama-3.1-8b-instruct` は廃止済み） | 同上（`MODEL`） |
| 答えの検証 | こちらで決めた順位の銘柄ごとに AI の理由を突き合わせる。理由文から、値（数字）を伴わずに指標の名前だけが出てくる節（「配当性向はなし」など、渡していない項目への言及。2026-10-22 の本番で出た）を取り除き、文の終わりを取ったときは「〜しており」を「〜している」と言い切りに直す（`tidy_reason`）。理由が返ってこない・空・200文字を超える銘柄はその1件だけ捨て、候補にない銘柄の理由は無視する。残りを順位順に詰め、5件（`MIN_PICKS`）以上なら評価（`grade`）つきで保存して捨てた分をログに出す。5件に届かなければ保存せずエラーをログに出す | `domain/src/recommend.rs`（`validate_picks`） |

画面（AIレコメンドのタブ）には「AIによる参考情報であり投資助言ではありません」を明記し、★の数で評価を、理由の文章とは別に根拠の数字（方針との差・直近四半期の伸び・4四半期合計の伸び）と注目テーマのタグを出す。評価を付ける前に保存した日の行は `grade` が NULL で、★は出ない。
